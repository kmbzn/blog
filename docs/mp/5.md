# 5. ARM Instruction Set Architecture I

## Topics

- ARM assembly code의 구조와 expression
- 데이터, 정렬, macro, section 및 symbol binding directive

## Structure of ARM Assembly Code

- Symbol은 label 등 참조 가능한 객체를 지칭하는 이름
- `msg`, `main`, `printf`가 symbol의 예
- 아래는 강의의 전통적 ARM assembly 예제이며 C library의 `printf`가 연결된 환경 가정

```asm
.data
msg:
    .asciz "Hello World\n"

.text
.global main
main:
    stmfd sp!, {lr}
    ldr r0, =msg
    bl printf
    mov r0, #0
    ldmfd sp!, {lr}
    mov pc, lr
```

- `.data`는 데이터 section, `.text`는 코드 section 선택
- `.global main`은 다른 object file에서 `main` 참조 허용
- 문자열 주소를 `r0`에 넣어 전달하고 `r0`에 반환값 `0` 기록
- 위 코드는 assembly 구조 설명용 원문 예시이며 Cortex-M용 startup 및 ABI 정렬까지 갖춘 완결 프로그램이라는 의미는 아님.

## Syntax of Assembly

- Label, directive, instruction 및 macro invocation으로 구성
- Label 끝에는 코드 문법상 `:` 사용
- 일반 statement는 newline 또는 `;`에서 종료
- Directive는 `.`으로 시작하며 processor가 실행하는 명령어와 구별됨.
- `//`는 한 줄 주석, `/* ... */`는 여러 줄 또는 statement 내부 주석

```asm
add r0, r1, r2
lab: .word 42
lab1: lab2:
add r0, r1, r2; bx lr
add /*dst*/r0, /*lhs*/r1, /*rhs*/r2
```

- 마지막 줄의 주석은 whitespace가 가능한 위치에 삽입된 예

## Assembly Expressions

- 정수 literal과 symbol reference를 연산자로 조합한 식
- Instruction operand와 directive argument에 사용 가능
- Assembler가 계산하며 CPU의 runtime 계산이 아님.
- 외부 symbol은 assembler가 relocation 정보를 남기고 linker가 최종 주소 해결 가능

| 구성 | 표기 |
| --- | --- |
| Decimal | `42` |
| Hexadecimal | `0x2A` |
| Octal | `052` |
| Binary | `0b101010` |
| Unary | `+`, `-`, `~` |
| Arithmetic | `+`, `-`, `*`, `/`, `%` |
| Logical | `&&`, `\|\|` |
| Bitwise | `&`, `\|`, `^`, `>>`, `<<` |
| Comparison | `==`, `!=`, `<`, `>`, `<=`, `>=` |

- `.`은 현재 output section에서 다음 instruction 또는 data를 배치할 location
- 같은 section 안의 label 차이는 거리 계산에 사용 가능

```asm
orr r0, r0, #(1 << 23)
func:
    ldr r0, =data + 4
    ldr r0, [r0]
    bx lr
data:
    .word 1
    .word 2
size:
    .word end - start
start:
    .word 123
    .word 42
    .word 4523534
end:
```

- `1 << 23`은 assembly 시 계산되는 bit mask
- `data + 4`는 두 번째 word의 주소이며 실제 값 `2`를 읽으려면 추가 `LDR` 필요
- 강의의 `LDR r0, =data+4`가 곧바로 `2`를 읽는다는 주석은 주소와 값의 구별 필요
- `end - start`는 `12` bytes

## Assembly Directives

- String definition, data definition, alignment 및 space-filling
- Macro, origin, conditional assembly
- Section 선택과 symbol binding
- Directive는 assembler에 주는 지시이며 runtime instruction이 아님.

## String Definition Directives

| Directive | 저장 내용 |
| --- | --- |
| `.ascii "string"` | 문자열 byte만 저장 |
| `.asciz "string"` | 문자열 끝에 null byte 추가 |
| `.string "string"` | 문자열 끝에 null byte 추가 |

```asm
hello:
    adr r0, str_hello
    b print
str_hello:
    .asciz "Hello, world!\n"
```

- 문자열은 현재 section에 배치됨.
- `ADR`은 label 주소를 구하는 용도, `B`는 문자열을 instruction으로 실행하지 않고 출력 처리로 분기하는 예

## Data Definition Directives

| Directive | 항목 하나의 크기 |
| --- | --- |
| `.byte` | `1` byte |
| `.hword` | `2` bytes |
| `.word` | `4` bytes |
| `.quad` | `8` bytes |
| `.octa` | `16` bytes |

- 쉼표로 여러 expression을 전달하면 각 값을 순서대로 할당하고 초기화함.

```asm
.byte 42
.word 15532
.word extern_symbol
.hword end - start
.word extern_symbol - .
```

- 외부 symbol 주소나 현재 위치와의 상대 offset도 저장 가능
- `end - start`의 두 label은 같은 assembly file의 같은 section에 정의되어야 함.
- Label 두 개의 section은 차이를 저장하는 directive의 section과는 달라도 됨.

## Alignment Directives

| Directive | 정렬 경계 |
| --- | --- |
| `.balign num_bytes, fill_value` | `num_bytes` bytes |
| `.p2align exponent, fill_value` | $2^{\mathrm{exponent}}$ bytes |
| ARM의 `.align exponent, fill_value` | $2^{\mathrm{exponent}}$ bytes |

- 필요한 만큼 padding을 넣어 현재 location을 경계에 맞춤.
- `fill_value`는 선택적인 padding 값
- 강의의 `.balign` 경계는 `2`의 거듭제곱 사용

```asm
get_val:
    ldr r0, value
    adds r0, #1
    bx lr
    .p2align 2
value:
    .word 42

    .p2align 4
func1:
    bx lr
    .p2align 4
func2:
    bx lr
```

- 앞의 세 명령어가 각각 `16` bits라면 `6` bytes 뒤의 word에 padding 필요
- `.p2align 2`는 `4`-byte data 정렬, `.p2align 4`는 `16`-byte 함수 진입점 정렬
- 함수 경계 정렬은 instruction fetch 및 cache 활용에 영향

## Space-Filling Directives

- `.space count, value`는 `count` bytes를 같은 byte 값으로 채움.
- `.fill count, size, value`는 `size` bytes 크기의 항목을 `count`개 생성
- 선택 인수 생략 시 `.space`의 값은 `0`, `.fill`의 크기는 `1`, 값은 `0`

```asm
.space 8, 0
.fill 4, 2, 0x1234
```

- 첫 directive는 `8`개의 zero byte, 두 번째는 `2`-byte 값 `4`개 할당

## Macro Directives

- `.macro`와 `.endm` 사이의 본문을 macro 이름으로 재사용
- Macro 내부 parameter는 `\name`으로 참조하며 호출 때 인수로 치환됨.
- `.exitm`으로 macro 확장 조기 종료 가능

| Parameter 형식 | 의미 |
| --- | --- |
| `name:req` | 필수 인수 |
| `name:vararg` | 남은 인수를 모두 받는 마지막 parameter |
| `name=value` | 기본값 지정 |

```asm
.macro pascal_string, str
    .byte 2f - 1f
1:
    .ascii "\str"
2:
.endm

.data
hello:
    pascal_string "Hello"
goodbye:
    pascal_string "Goodbye"
```

- Pascal-style string은 null terminator 대신 앞에 길이 byte 배치
- `hello`는 길이 `5`와 `Hello`, `goodbye`는 길이 `7`과 `Goodbye` 저장
- Numeric local label의 `f`는 가까운 forward label, `b`는 가까운 backward label 참조
- Macro 확장은 subroutine call과 달리 호출 위치마다 본문을 생성함.

## Org Directives

- `.org new_location, fill_value`는 현재 section의 location counter를 앞으로 이동
- 건너뛴 공간은 기본적으로 zero byte로 채우며 선택적으로 byte 값 지정 가능
- `new_location`은 section 시작 기준의 절대 offset 또는 현재 section 내부 위치 expression
- 이전 위치로 되돌아가려 하면 오류 발생
- 아래는 강의에서 directive 용도를 보여 주는 AArch64 vector entry 예시이며 Cortex-M vector table과 구별 필요

```asm
.macro exc_tab_entry, num
1:
    mov x0, #\num
    b unhandled_exception
    .org 1b + 0x80
.endm

.section vectors, "ax"
exc_tab_entry 0
exc_tab_entry 1
```

- 각 entry는 code와 padding을 합해 `128` bytes
- Code가 `128` bytes보다 크면 `.org`가 backward 이동을 요구하므로 오류 검출

## Conditional Assembly Directives

- `.if`, `.elseif`, `.else`, `.endif`로 출력할 code를 assembly 시 선택
- `.if expr`와 `.ifne expr`는 nonzero일 때, `.ifeq expr`는 zero일 때 해당 본문 선택
- 실행 시 조건을 검사하는 branch와 구별되는 처리

```asm
.macro get_imm, reg, imm
    .if \imm >= 0x10000
        movw \reg, #(\imm & 0xffff)
        movt \reg, #(\imm >> 16)
    .else
        movw \reg, #\imm
    .endif
.endm

get_constants:
    get_imm r0, 42
    get_imm r1, 0x12345678
    bx lr
```

- `42`는 `MOVW` 하나, `0x12345678`은 `MOVW`와 `MOVT` 두 명령어로 확장

## Section Directives

- `.section name`으로 ELF의 출력 대상 section 선택
- Flags, type, entry size, group 및 linkage 등 추가 속성 지정 가능
- `.text`는 code, `.data`는 초기값이 있는 writable data, `.bss`는 zero-initialized storage
- `.rodata`는 read-only data의 section 이름이며 GNU assembler에서는 `.section .rodata`로 선택 가능

```asm
.text
get_value:
    movw r0, #:lower16:value
    movt r0, #:upper16:value
    ldr r0, [r0]
    bx lr

.data
value:
    .word 42
```

- `value` 주소의 하위와 상위 halfword를 각각 구성한 후 실제 저장값 읽기
- Section 전환은 출력 위치를 바꾸는 지시이며 CPU가 runtime에 수행하는 동작이 아님.

## Symbol Binding Directives

| Directive | Link 시 의미 |
| --- | --- |
| `.global symbol` | 다른 object file에서 참조 가능, 일반적인 중복 strong definition은 오류 |
| `.local symbol` | 해당 object file 내부에서만 사용하므로 파일 간 같은 이름 사용 가능 |
| `.weak symbol` | Weak definition 허용, 같은 이름의 strong global definition이 우선 |

```asm
.global get_val
get_val:
    ldr r0, value
    bx lr
value:
    .word 0x12345678

    bl printf
    .weak debug_trace
    bl debug_trace
```

- Weak symbol은 중복 정의를 허용하며 같은 이름의 strong global definition이 있으면 해당 정의 우선
- 정의된 `value`는 별도 global 지시가 없으면 local binding
- 현재 file에 정의되지 않은 `printf`는 다른 object 또는 library에서 해결할 외부 참조
- `debug_trace`는 정의가 있으면 연결하고 없으면 unresolved weak reference로 처리
- 강의는 정의되지 않은 weak call을 다음 명령으로 넘기는 linker 동작을 예시로 사용하며 실제 처리는 target과 linker 규칙에 의존함.
