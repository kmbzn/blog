# 3. Overview of ARM Architecture & Cortex-M Processors

## Topics

- ARM architecture, instruction set 및 processor family
- Cortex-M의 구성과 programmer’s model

## ARM Architecture Overview

- Arm은 모바일 및 embedded processor 분야의 주요 설계 기업
- Chip과 architecture 설계를 판매하며 silicon을 직접 제조하지 않음.
  - 설계 라이선스와 royalty를 통한 사업 운영
- Processor IP 외에도 GPU, system controller, interconnect, debug 및 개발 도구 제공
- RISC 기반의 load-store architecture
  - 메모리와 register 사이의 전송은 load/store 명령어 담당
  - ALU 연산은 register의 피연산자 중심
  - 다수의 범용 register 및 전력 대비 성능 중시
- 전통적 ARM 명령어는 고정 `32`-bit이며 Thumb-2는 `16`-bit와 `32`-bit 혼합
- Armv1–Armv7은 `32`-bit architecture이며 Armv8–Armv9은 `64`-bit architecture 포함
  - Armv8-M과 같은 microcontroller profile은 `32`-bit 실행 사용

| Processor family | 목적 | Pipeline과 interrupt | 주요 기능 | 응용 |
| --- | --- | --- | --- | --- |
| Cortex-A | Application 처리 | 높은 clock과 긴 pipeline | MMU, cache, NEON, TrustZone | 모바일 기기, server, 고성능 embedded OS |
| Cortex-R | Real-time 처리 | 예측 가능한 낮은 interrupt latency | MPU, cache, TCM | 자동차, 산업 제어, 저장 장치 |
| Cortex-M | Microcontroller | 짧은 pipeline과 낮은 전력 소모 | NVIC, 선택적 MPU, WIC | 센서, IoT, 소형 제어 장치 |

- MMU는 가상 주소 변환 및 보호, MPU는 메모리 영역별 접근 보호 담당
- TCM은 예측 가능한 접근 시간을 위한 tightly coupled memory
- WIC는 저전력 상태에서 interrupt에 의한 wake-up 지원

## Functional Evolutions by Architectures

| 목적 | 주요 확장과 흐름 |
| --- | --- |
| 코드 크기 감소 | Armv4T의 Thumb에서 Armv6T2의 Thumb-2로 확장 |
| Bytecode 실행 가속 | Jazelle DBX, 이후 Jazelle RCT 및 ThumbEE |
| 연산 능력 확장 | VFPv1/v2, SIMD, VFPv3/v4, Advanced SIMD인 NEON |

- 각 기능은 architecture profile 및 구현 선택에 따라 지원 여부가 달라지는 확장

## Instruction Sets

| Instruction set | 명령어 길이 | 특징 |
| --- | --- | --- |
| ARM, A32 | `32` bits | 전통적 ARM state 명령어 |
| 초기 Thumb | `16` bits 중심 | 작은 코드 크기와 좁은 메모리 bus에 유리 |
| Thumb-2, T32 | `16` 또는 `32` bits | 코드 밀도와 표현력의 절충 |
| AArch64, A64 | `32` bits | `64`-bit register 및 주소 체계용 명령어 |

- Architecture의 register 폭과 개별 명령어 encoding 길이는 서로 다른 개념
- `20 MHz`에서의 Dhrystone 성능은 메모리 폭에 따라 달라짐.
- `32`-bit memory에서는 ARM의 처리량이 유리할 수 있으며, `16`-bit memory에서는 Thumb의 작은 fetch 크기가 유리함.
- `16`-bit memory와 `32`-bit stack의 조합도 성능에 영향
- Thumb-2는 Thumb 대비 약 `25%` 성능 향상, ARM 대비 약 `26%` 코드 크기 감소
- 성능과 코드 크기의 개선 폭은 실행 workload와 processor 구현에 따라 달라짐.

## Cortex-M Processor Family

| Processor | Architecture | 주요 특징 |
| --- | --- | --- |
| Cortex-M0 | Armv6-M | 약 `12K` gates부터 시작하는 저비용 초저전력 설계 |
| Cortex-M0+ | Armv6-M | M0와 유사한 programmer’s model, single-cycle I/O, vector table relocation |
| Cortex-M1 | Armv6-M | FPGA용 설계와 FPGA memory block 기반 TCM |
| Cortex-M3 | Armv7-M | Thumb-2, hardware divide, MAC, debug 및 trace |
| Cortex-M4 | Armv7E-M | M3의 기능에 DSP, SIMD, 빠른 MAC 및 선택적 single-precision FPU 추가 |
| Cortex-M7 | Armv7E-M | 고성능 처리, cache, TCM, 선택적 single/double-precision FPU |
| Cortex-M23 | Armv8-M Baseline | 저비용 저전력 설계 및 선택적 TrustZone |
| Cortex-M33 | Armv8-M Mainline | 유연한 시스템 구성, 선택적 DSP, FPU, TrustZone |

- M0와 M0+는 Von Neumann 계열, M3/M4/M7은 instruction/data 접근 경로를 분리한 Harvard 계열
- M0 계열은 제한된 Thumb 명령어와 `1` 또는 `32` cycle multiply, hardware divide 미지원
- M3는 single-cycle multiply, hardware divide와 saturation 지원, DSP extension과 FPU 미지원
- M4/M7은 DSP extension 지원 및 선택적 FPU 제공
- Cortex-M23은 저비용·초저전력 microcontroller용 Baseline profile
- Cortex-M33은 복잡한 embedded 처리와 유연한 시스템 구성을 위한 Mainline profile

## Cortex-M3 Processor

- Cortex-M3 core와 system peripheral, bus 및 debug 구성 요소를 통합한 processor
- Core의 주요 구성은 Harvard architecture, `3`-stage pipeline, Thumb-2, ALU, hardware divide 및 single-cycle multiply
- NVIC는 nested vectored interrupt와 우선순위 관리 담당
- 구현에 따라 `1–240`개의 external interrupt와 우선순위 수준 구성
- ICode bus는 instruction fetch, DCode bus는 code 영역의 data access, system bus는 그 밖의 메모리와 장치 접근 담당
- Bus matrix가 core와 memory 및 peripheral 연결
- SWD/JTAG, breakpoint, data watchpoint, trace와 선택적 ETM 제공
- 선택적 MPU를 통한 접근 보호
- TSMC `0.18 μm`, `50 MHz` 초기 구현의 gate count
  - Core 약 `30K`, 전체 processor 약 `60K`
  - 선택적 ETM과 MPU의 gate count 제외

## Programmer’s Model

- C로 프로그래밍 가능하며 assembly 사용이 필수는 아님.
- Stack 기반 exception model로 exception 진입 시 복귀에 필요한 기본 상태를 hardware가 자동 저장함.
- 기본 exception frame은 `r0–r3`, `r12`, `LR`, `PC`, `xPSR`
- 일반 실행은 Thread mode, exception 처리는 Handler mode
- Vector table에 exception handler 주소 보관

| Register | 역할 |
| --- | --- |
| `r0–r7` | Low general-purpose register |
| `r8–r12` | High general-purpose register |
| `r13`, `SP` | Stack pointer, 실제로 `MSP`와 `PSP` 중 하나 선택 |
| `r14`, `LR` | Subroutine 복귀 주소 |
| `r15`, `PC` | 프로그램 실행 흐름 |

- 초기 `16`-bit Thumb encoding의 high register 접근은 주로 `MOV`, `ADD`, `CMP` 등으로 제한됨.
- Thumb-2에서는 명령어 및 encoding에 따라 더 넓은 register 사용 가능

## Stack Pointers

- `r13`에 banked register인 `MSP`와 `PSP` 중 하나가 노출되는 구조
- `MSP`는 reset 직후의 기본 stack이며 Handler mode에서 항상 사용함.
- `PSP`는 Thread mode의 application task용 stack 분리에 활용 가능
- Thread mode의 선택은 `CONTROL.SPSEL`로 결정하며 stack 선택 자체가 privilege를 뜻하지는 않음.

## Program Counter and Instruction State

- 명령어에서 `PC`를 읽으면 현재 명령어 주소에 `4`를 더한 값 관찰
- 주소 `0x1000`의 `MOV r0, pc` 실행 결과는 `r0 = 0x1004`
- `PC`를 목적지로 갱신하는 명령어는 실행 흐름 변경
- Cortex-M3는 Thumb state만 지원함.
- `BX`, `BLX` 및 handler vector와 같은 상태 선택 대상 주소의 bit `0`은 `1`이어야 함.
- 실제 instruction 주소는 halfword 정렬이며 `PC`를 읽을 때 bit `0`은 `0`
- 일반 ARM/Thumb interworking에서 target bit `0`이 `0`이면 ARM state를 선택하지만 Cortex-M3에서는 fault 원인
- Register branch는 target 주소의 bit `0`으로 Thumb state를 지정하며 직접 branch는 instruction에 encoding된 offset 사용

## Link Register

- `BL`이 다음 명령어로 돌아올 주소를 `LR`에 저장한 후 subroutine으로 이동함.
- Thumb 복귀 주소는 state 표시용 bit `0`을 포함함.
- `BX lr`로 caller에 복귀 가능

```asm
main:
      BL foo
      B done
foo:
      BX lr
done:
      B done
```

## Special Registers

- `PSR`, `PRIMASK`, `FAULTMASK`, `BASEPRI`, `CONTROL` 등의 특수 register
- `MRS`는 특수 register에서 범용 register로 읽기, `MSR`은 반대 방향 쓰기
- 두 명령어는 메모리 주소를 직접 피연산자로 사용하지 않음.

```asm
MRS r0, CONTROL
MSR CONTROL, r0
```

## Program Status Registers

- `APSR`, `IPSR`, `EPSR`을 통합해 부르는 이름이 `xPSR`

| 구성 | Bit | 의미 |
| --- | --- | --- |
| `APSR` | `N`, bit `31` | 결과의 sign bit |
| `APSR` | `Z`, bit `30` | 결과가 `0` |
| `APSR` | `C`, bit `29` | Carry 또는 subtraction에서 borrow 없음. |
| `APSR` | `V`, bit `28` | Signed overflow |
| `APSR` | `Q`, bit `27` | Sticky saturation flag |
| `EPSR` | `ICI/IT`, bits `26–25`, `15–10` | 중단 가능한 명령어 및 IT 실행 상태 |
| `EPSR` | `T`, bit `24` | Thumb state, 정상 실행 시 `1` |
| `IPSR` | Exception number, bits `8–0` | 현재 처리 중인 exception, Thread mode는 `0` |

- `IPSR`와 `EPSR`는 일반 소프트웨어 쓰기로 변경할 수 없음.
- `MRS`로 `EPSR`을 읽으면 `0` 반환
- Exception 진입 시 stack에 저장되는 `xPSR`에는 복귀에 필요한 execution state 포함
- `MSR`로 combined status를 지정해도 writable application flag만 갱신 가능

```asm
MRS r0, APSR
MRS r1, IPSR
MRS r2, PSR
MSR APSR_nzcvq, r0
```

## PRIMASK, FAULTMASK and BASEPRI

| Register | 기능 | 초기값 |
| --- | --- | --- |
| `PRIMASK` | `1`이면 configurable priority exception 차단, NMI와 HardFault 허용 | `0` |
| `FAULTMASK` | `1`이면 NMI를 제외한 exception 차단 | `0` |
| `BASEPRI` | `0`이 아니면 지정한 priority 값 이상인 configurable exception 차단 | `0` |

- Priority의 숫자가 작을수록 높은 우선순위
- `BASEPRI`의 priority field는 `8` bits이며 구현이 지원하는 상위 bit만 유효할 수 있음.
- Timing-critical 구간에서 `PRIMASK` 또는 `BASEPRI`를 일시적으로 사용 가능
- `FAULTMASK`는 손상된 task의 정리 등 특수 kernel 처리에 활용 가능
- Unprivileged 실행에서는 mask 변경 불가

```asm
MRS r0, BASEPRI
MRS r1, PRIMASK
MRS r2, FAULTMASK
MSR BASEPRI, r0
MSR PRIMASK, r1
MSR FAULTMASK, r2
```

## The Control Register

| Bit | `0` | `1` |
| --- | --- | --- |
| `CONTROL[0]`, `nPRIV` | Privileged Thread mode | Unprivileged Thread mode |
| `CONTROL[1]`, `SPSEL` | `MSP` 선택 | Thread mode에서 `PSP` 선택 |

- Cortex-M3의 Handler mode는 항상 privileged이며 `MSP` 사용
- Thread mode의 privileged code에서 `CONTROL` 변경 가능
- Unprivileged code가 직접 privileged 상태로 복귀하는 것은 불가하며 exception을 통한 제어 필요
- `CONTROL` 변경 뒤에는 `ISB`를 이용한 실행 동기화 필요

## Operation Modes and Privilege Levels

| 실행 종류 | Mode | Privilege | Stack |
| --- | --- | --- | --- |
| Reset 이후 일반 프로그램 | Thread | 기본 privileged, 이후 선택 가능 | `MSP` 또는 `PSP` |
| Exception handler | Handler | 항상 privileged | `MSP` |

- Unprivileged code는 `MRS`, `MSR` 사용에 제약이 있고 `CPS`로 interrupt mask 변경 불가
- NVIC, system timer, system control block 등 system resource 접근 제한
- MPU 구성에 따라 일반 메모리 및 peripheral 접근도 제한 가능
- Privileged code는 system resource를 구성할 수 있으나 MPU 등 설정에 따른 접근 규칙은 여전히 적용됨.
- Exception 발생 시 Handler mode 진입, exception return 시 저장된 Thread mode 상태 복구

      ┌───────────────────┐    Exception    ┌───────────────────┐
      │ Thread privileged ├────────────────▶│ Handler privileged│
      └─────────┬─────────┘                 └─────────┬─────────┘
                │ Set nPRIV                           │ Return
                ▼                                     ▼
      ┌───────────────────┐    Exception    ┌───────────────────┐
      │ Thread user       ├────────────────▶│ Saved thread state│
      └───────────────────┘                 └───────────────────┘

- Exception return은 exception 진입 전에 저장한 mode와 privilege 상태 복원

## Vector Tables

- Word 단위 entry 배열이며 일반 handler entry에는 Thumb 주소 저장
- 초기 base address는 `0x00000000`, 이후 `SCB.VTOR`로 relocation 가능
- Exception number에 `4`를 곱한 값이 table base로부터의 byte offset
- Entry `0`은 handler 주소가 아닌 초기 `MSP`

| Exception number | Offset | 용도 |
| --- | --- | --- |
| `0` | `0x00` | Initial `MSP` |
| `1` | `0x04` | Reset |
| `2` | `0x08` | NMI |
| `3` | `0x0C` | HardFault |
| `4` | `0x10` | MemManage |
| `5` | `0x14` | BusFault |
| `6` | `0x18` | UsageFault |
| `7–10` | `0x1C–0x28` | Reserved |
| `11` | `0x2C` | SVC |
| `12` | `0x30` | DebugMonitor |
| `13` | `0x34` | Reserved |
| `14` | `0x38` | PendSV |
| `15` | `0x3C` | SysTick |
| `16` 이후 | `0x40` 이후 | External interrupt |

## Reset Sequence

1. 주소 `0x00000000`의 word를 읽어 초기 `MSP` 설정
2. 주소 `0x00000004`의 reset vector 읽기
3. Vector의 bit `0`으로 Thumb state를 확인하고 reset handler의 instruction fetch 시작

- Stack 영역이 `0x20007C00–0x20007FFF`라면 빈 stack의 초기 `MSP` 예는 `0x20008000`
- 첫 word push는 `0x20007FFC`, 다음 push는 `0x20007FF8`에 저장함.
- Reset vector가 `0x00000101`이면 실제 첫 명령어 주소는 `0x00000100`
