# 6. ARM Instruction Set Architecture II

## Topics

- ARM instruction 형식, encoding 및 decoding
- 산술, 논리, bit 조작, data 이동과 barrel shifter

## Load-Store Architecture

- Memory access는 register와 memory 사이의 load/store
- ALU operation은 register의 값을 대상으로 하는 연산
- 메모리 변수 `x`를 증가시키려면 주소 준비, load, add, store 과정 필요

```asm
.text
    LDR r0, =x
    LDR r1, [r0]
    ADD r1, r1, #1
    STR r1, [r0]
.data
x:
    .word -2
```

- 실행 뒤 `x = -1`

## Assembly Instructions Supported

| 종류 | 주요 명령어 또는 기능 |
| --- | --- |
| Arithmetic and logic | Add, subtract, multiply, divide, shift, rotate |
| Data movement | Load, store, move |
| Compare and branch | Compare, test, if-then, branch, compare-and-branch-on-zero |
| Miscellaneous | Breakpoint, wait for event, interrupt mask, memory barrier, synchronization barrier |

## ARM Instruction Format

- 일반적인 형식은 `mnemonic destination, source1, source2`
- 명령어마다 operand 수가 다르며 operand가 없는 명령어도 존재
- 첫 operand는 보통 목적지 register, 두 번째는 source register
- 마지막 operand는 register, immediate 또는 shifted register 등으로 구성
- Memory operand에는 base register와 offset 사용 가능

```asm
ADD r0, r2, r3
ADD r1, r2, r3
ADD r1, r3
ADD r1, r2, #4
ADD r1, #15
```

- 첫 줄은 `r0 = r2 + r3`
- 두 operand 형태는 목적지의 기존 값도 source로 사용함.
- UAL은 ARM과 Thumb의 공통 문법이며 전통적 Thumb 문법의 두 operand 형태와 구별 가능

## Encoding Thumb Instructions

- `16`-bit Thumb는 제한된 bit 안에 opcode, register 및 immediate 배치
- Shift/add/subtract/move/compare, data processing, special data/branch, literal load, single load/store, PC/SP-relative address, miscellaneous, multiple transfer 및 branch로 분류

| `16`-bit encoding의 시작 bit | 주요 분류 |
| --- | --- |
| `00` | Shift, add, subtract, move, compare |
| `010000` | Data processing |
| `010001` | High register operation 및 branch exchange |
| `01001` | Literal pool load |
| `0101`, `011`, `100` | Single load/store |
| `10100`, `10101` | PC 또는 SP-relative address |
| `1011` | Miscellaneous |
| `11000`, `11001` | Store/load multiple |
| `1101` | Conditional branch, supervisor call |
| `11100` | Unconditional branch |

- `ORR r1, r0`의 `16`-bit encoding은 `0x4301`
- Bit `15–10`은 `010000`, operation field `9–6`은 `1100`, source `5–3`은 `000`, destination `2–0`은 `001`
- 해당 연산은 `r1 = r1 | r0`이며 `16`-bit encoding의 flag 동작은 실행 context에 따라 확인 필요
- 첫 halfword의 bit `15–11`이 `11101`, `11110`, `11111`이면 `32`-bit Thumb instruction의 시작
- `32`-bit Thumb는 multiple/dual/exclusive load-store, shifted-register 및 immediate data processing, branch/control, coprocessor, multiply, long multiply 및 divide 등 표현

| Fetch한 halfword | Decoding |
| --- | --- |
| 첫 번째 `0xF04F` | Modified-immediate data processing, `S = 0`, `Rn = 1111`인 move 형태 |
| 두 번째 `0x0003` | `Rd = r0`, immediate `3` |
| 전체 명령어 | `MOV.W r0, #3` |

- `32`-bit 명령어는 메모리에서 순서대로 읽은 두 halfword를 결합해 해석함.

## ARM Instruction Code Format

- 강의의 이 부분은 A32 encoding 비교이며 Cortex-M3에서 실행하는 Thumb-2 encoding과 구별 필요

| Bit | A32 data-processing field |
| --- | --- |
| `31–28` | Condition |
| `27–26` | Data processing 분류 `00` |
| `25` | Register 또는 immediate 선택 |
| `24–21` | Opcode |
| `20` | Flag update `S` |
| `19–16` | Source `Rn` |
| `15–12` | Destination `Rd` |
| `11–0` | Operand2 |

- Register operand는 shift amount, shift type 및 `Rm`으로 구성 가능
- Immediate operand는 `8`-bit literal과 rotate field로 구성

## ARM Load and Store Code Format

| Bit | A32 single load/store field |
| --- | --- |
| `31–28` | Condition |
| `27–26` | 분류 `01` |
| `25` | Immediate 또는 shifted register offset 선택 `I` |
| `24` | Pre/post-index 선택 `P` |
| `23` | Offset 가산/감산 선택 `U` |
| `22` | Byte/word 선택 `B` |
| `21` | Base write-back `W` |
| `20` | Load/store 선택 `L` |
| `19–16` | Base `Rn` |
| `15–12` | 전송 register `Rd` |
| `11–0` | Offset |

- A32 single transfer는 `I = 0`이면 `12`-bit immediate, `I = 1`이면 shifted register offset
- 강의 그림의 offset 선택 표기는 위 실제 field 의미와 구별 필요

## First Assembly

```asm
.syntax unified
.cpu cortex-m3
.thumb
.equ STACK_TOP, 0x20000800
.text
.global _start
_start:
    .word STACK_TOP, start
.thumb_func
start:
    movs r0, #10
    movs r1, #0
loop:
    adds r1, r1, r0
    subs r0, r0, #1
    bne loop
deadloop:
    b deadloop
```

- Vector의 첫 word는 초기 stack top, 두 번째 word는 Thumb reset entry
- `.thumb_func`는 `start`를 Thumb function symbol로 표시함.
- 각 반복에서 현재 `r0`를 누적하고 `r0`를 감소시킴.
- `SUBS`의 `Z`가 `0`인 동안 반복, 완료 시 `r0 = 0`, `r1 = 55`
- 실제 reset 실행에는 linker가 vector를 적절한 boot 주소에 배치해야 함.

## Arithmetic and Logic Instructions

- 기본 표기는 `Operation{cond}{S} Rd, Rn, Operand2`
- `cond`는 조건, `S`는 condition flag 갱신 요청
- Thumb에서 일반 명령어의 conditional execution은 IT block 규칙 적용

| 명령어 | 연산 |
| --- | --- |
| `ADD` | `Rd = Rn + Op2` |
| `ADC` | `Rd = Rn + Op2 + C` |
| `SUB` | `Rd = Rn - Op2` |
| `SBC` | `Rd = Rn - Op2 + C - 1` |
| `RSB` | `Rd = Op2 - Rn` |
| `MUL` | 곱의 하위 `32` bits |
| `MLA` | `Rd = Ra + Rn * Rm`의 하위 `32` bits |
| `MLS` | `Rd = Ra - Rn * Rm`의 하위 `32` bits |
| `SDIV` | Signed integer division |
| `UDIV` | Unsigned integer division |
| `SSAT` | 지정한 signed bit 폭으로 saturation |
| `USAT` | 지정한 unsigned bit 폭으로 saturation |
| `CLZ` | 최상위부터 연속된 zero bit 수 |
| `SBFX`, `UBFX` | Bit field 추출 후 sign/zero extension |

- Shift는 `LSL`, `LSR`, `ASR`, `ROR`, `RRX`
- Bitwise logic은 `AND`, `ORR`, `EOR`, `ORN`, `MVN`, `BIC`
- Bit field 조작은 `BFC`, `BFI`, 순서 반전은 `RBIT`, `REV`, `REV16`, `REVSH`
- `SSAT`는 $-2^{n-1}$부터 $2^{n-1}-1$, `USAT`는 $0$부터 $2^n-1$ 범위로 제한
- 범위를 벗어나 saturation이 발생하면 sticky flag `Q` 설정

## Setting Condition Flags

```asm
LDR r0, =0xFFFFFFFF
LDR r1, =0x00000001
ADDS r0, r0, r1
stop:
    B stop
```

- 결과는 `r0 = 0x00000000`, `N = 0`, `Z = 1`, `C = 1`, `V = 0`
- Unsigned carry와 signed overflow는 서로 다른 조건
- `S` suffix를 사용할 수 있는 명령어 및 갱신되는 flag는 instruction별 차이 존재
- 강의의 `0xFFFFFFFFF`는 `32`-bit 예제에 맞춰 `0xFFFFFFFF`로 표기함.

## 64-bit Addition

- `64`-bit 정수는 상위와 하위 `32`-bit register 한 쌍으로 표현
- 하위 덧셈이 만든 carry를 상위 덧셈에 전달
- 개념 예는 `0x00000002FFFFFFFF + 0x0000000400000001 = 0x0000000700000000`

```asm
LDR r0, =0xFFFFFFFF
LDR r1, =0x00002222
LDR r2, =0x00000001
LDR r3, =0x00000444
ADDS r4, r2, r0
ADC r5, r3, r1
```

- `r1`과 `r0`가 첫 정수의 상위/하위, `r3`과 `r2`가 두 번째 정수의 상위/하위
- 코드 결과는 `r5 = 0x00002667`, `r4 = 0x00000000`
- 두 연산 사이에 carry를 변경하는 다른 명령어를 넣으면 안 됨.

## 64-bit Subtraction

```asm
LDR r0, =0xFFFFFFFF
LDR r1, =0x00000002
LDR r2, =0x00000001
LDR r3, =0x00000004
SUBS r4, r0, r2
SBC r5, r1, r3
```

- 계산은 `0x00000002FFFFFFFF - 0x0000000400000001`
- 하위 결과 `r4 = 0xFFFFFFFE`, borrow가 없으므로 `C = 1`
- 상위 결과 `r5 = 0xFFFFFFFE`, 전체 결과는 `0xFFFFFFFEFFFFFFFE`
- Subtraction의 `C = 1`은 borrow 없음, `C = 0`은 borrow 발생

## Short Multiplication

```asm
MUL r6, r4, r2
MLA r6, r4, r1, r0
MLS r6, r4, r1, r0
```

- `MUL`의 하위 `32`-bit 결과는 signed/unsigned 해석과 관계없이 동일
- 별도 Cortex-M3 `UMUL` 명령어가 있는 것은 아니며 강의의 해당 표기는 `MUL`로 구별함.
- `MLA`는 `r4 * r1 + r0`, `MLS`는 `r0 - r4 * r1`
- 강의의 `MLS` 설명 중 곱에서 accumulator를 빼는 방향은 실제 연산과 반대이므로 주의 필요

## Long Multiplication

| 명령어 | `64`-bit 결과 |
| --- | --- |
| `UMULL RdLo, RdHi, Rn, Rm` | Unsigned 곱 |
| `SMULL RdLo, RdHi, Rn, Rm` | Signed 곱 |
| `UMLAL RdLo, RdHi, Rn, Rm` | 기존 register 쌍에 unsigned 곱 누적 |
| `SMLAL RdLo, RdHi, Rn, Rm` | 기존 register 쌍에 signed 곱 누적 |

```asm
UMULL r3, r4, r0, r1
SMULL r3, r4, r0, r1
UMLAL r3, r4, r0, r1
SMLAL r3, r4, r0, r1
```

- 각 줄은 별도 instruction 형태의 예이며 하위 결과는 `r3`, 상위 결과는 `r4`

## Bitwise Logic

| 명령어 | 연산 |
| --- | --- |
| `AND Rd, Rn, Op2` | `Rn & Op2` |
| `ORR Rd, Rn, Op2` | `Rn \| Op2` |
| `EOR Rd, Rn, Op2` | `Rn ^ Op2` |
| `ORN Rd, Rn, Op2` | `Rn \| ~Op2` |
| `BIC Rd, Rn, Op2` | `Rn & ~Op2` |
| `MVN Rd, Op2` | `~Op2` |

- 강의의 `r0 = 0xD5555555`, `r1 = 0xAAABAAAB`에 대해 `AND` 결과는 `0x80010001`, `ORR` 결과는 `0xFFFFFFFF`
- `r0 = 0xFFFFFFFF`, `r1 = 0x0000000F`의 `BIC` 결과는 `0xFFFFFFF0`
- `BIC`은 mask가 `1`인 위치만 clear하고 나머지 bit 보존

## Bit Field Clear and Insert

```asm
BFC r4, #8, #12
BFI r9, r2, #8, #12
```

- `BFC`는 `r4`의 bit `8–19`를 `0`으로 clear
- `BFI`는 `r2`의 bit `0–11`을 `r9`의 bit `8–19`에 삽입
- 두 연산 모두 대상 field 밖의 bit는 보존
- `lsb`는 시작 bit, `width`는 bit 개수

## Bitwise and Boolean Operators

- C의 `&`, `|`, `~`는 개별 bit 연산
- `&&`, `||`, `!`는 zero/nonzero를 false/true로 해석하고 결과를 `0` 또는 `1`로 생성
- `0x10 & 0x01`은 `0`, `0x10 && 0x01`은 `1`
- `32`-bit unsigned 값의 `~0x01u`는 `0xFFFFFFFE`, `!0x01`은 `0`
- `&&`와 `||`는 short-circuit 평가 적용

## Check, Set, Clear and Toggle a Bit in C

```c
bit = a & (1u << k);
a |= 1u << k;
a &= ~(1u << k);
a ^= 1u << k;
```

| 줄 | 기능 | `k = 5`일 때 |
| --- | --- | --- |
| `1` | 선택 bit 검사 | 결과는 `0` 또는 `0x20` |
| `2` | 선택 bit 설정 | bit `5`를 `1`로 변경 |
| `3` | 선택 bit 해제 | bit `5`를 `0`으로 변경 |
| `4` | 선택 bit 반전 | bit `5`를 기존 값의 반대로 변경 |

- 그 외 bit는 보존됨.
- Boolean 결과가 필요하면 `(a & (1u << k)) != 0` 사용
- `32`-bit unsigned 값에서는 `k`의 범위를 `0–31`로 제한
- XOR는 `0 ^ 1 = 1`, `1 ^ 1 = 0`이므로 초기값을 몰라도 toggle 가능

## Reverse Order

| 명령어 | 동작 | 입력 | 결과 |
| --- | --- | --- | --- |
| `RBIT` | Word 전체 bit 순서 반전 | `0x12345678` | `0x1E6A2C48` |
| `REV` | Word의 byte 순서 반전 | `0x12345678` | `0x78563412` |
| `REV16` | 각 halfword 내부의 byte 교환 | `0x12345678` | `0x34127856` |
| `REVSH` | 하위 halfword의 byte 교환 후 sign extension | `0x33448899` | `0xFFFF9988` |

- `REV`는 byte order 변환에 활용 가능하며 bit 순서를 뒤집는 `RBIT`과 구별 필요
- `REV16`은 상위/하위 halfword의 위치를 서로 바꾸지 않음.
- `REVSH`의 sign extension은 byte 교환 뒤의 bit `15` 기준

## Sign and Zero Extension

- Sign extension은 작은 signed 값의 sign bit를 상위 bit에 복제
- Zero extension은 상위 bit를 `0`으로 채움.
- `int8_t`의 `-1`인 `0xFF`를 `int32_t`로 변환하면 `0xFFFFFFFF`
- `int16_t`의 `-2`인 `0xFFFE`를 변환하면 `0xFFFFFFFE`

| 명령어 | 추출 및 확장 |
| --- | --- |
| `SXTB` | 하위 byte를 sign extend |
| `SXTH` | 하위 halfword를 sign extend |
| `UXTB` | 하위 byte를 zero extend |
| `UXTH` | 하위 halfword를 zero extend |

- 선택적으로 추출 전에 `ROR #8`, `#16`, `#24` 적용 가능
- 입력 `0x55AA8765`에 대한 결과는 `SXTB = 0x00000065`, `SXTH = 0xFFFF8765`, `UXTB = 0x00000065`, `UXTH = 0x00008765`

## Move Data between Registers

```asm
MOV r4, r5
MVN r4, r5
MOV r1, r2, LSL #3
MOV r0, pc
MOV r1, sp
MRS r0, CONTROL
MSR CONTROL, r0
```

- 각 줄은 독립적인 형태의 예
- `MOV`는 복사, `MVN`은 bitwise NOT, shifted `MOV`는 shift 결과 복사
- `PC`는 `r15`, `SP`는 `r13`, `LR`은 `r14`
- 특수 register 이동은 `MRS`와 `MSR` 사용

## Move Immediate Number to Register

```asm
MOVW r0, #0x4321
MOVT r0, #0x8765
```

- `MOVW`는 하위 `16` bits를 기록하고 상위 `16` bits를 `0`으로 설정
- `MOVT`는 상위 `16` bits를 기록하고 하위 `16` bits 보존
- 순서대로 실행하면 `r0 = 0x87654321`
- 두 명령어의 순서를 바꾸면 마지막 `MOVW`가 상위 halfword를 지우므로 `0x00004321`
- `MOV Rd, #const`는 해당 encoding이 표현 가능한 immediate만 사용 가능

## Barrel Shifter

- ALU의 operand에 shift 또는 rotate를 결합할 수 있는 hardware
- 별도 shift 결과 register와 추가 명령어를 줄이는 데 활용 가능

| 종류 | 동작 | 밖으로 밀린 bit |
| --- | --- | --- |
| `LSL` | 왼쪽 이동, 하위에 `0` 삽입 | 왼쪽에서 제거 |
| `LSR` | 오른쪽 이동, 상위에 `0` 삽입 | 오른쪽에서 제거 |
| `ASR` | 오른쪽 이동, 상위에 sign bit 복제 | 오른쪽에서 제거 |
| `ROR` | 오른쪽에서 빠진 bit를 왼쪽으로 순환 | Word 안에서 순환 |
| `RRX` | 기존 carry를 bit `31`로 넣고 bit `0`을 carry로 이동 | Carry를 포함한 `33`-bit 순환 |

- Left rotate는 다른 크기의 right rotate로 대체 가능

```asm
ADD r1, r0, r0, LSL #3
ADD r1, r0, r0, LSR #3
ADD r1, r0, r0, ASR #3
```

- 첫 줄은 `r1 = r0 + (r0 << 3)`, 즉 `9 * r0`의 하위 `32` bits
- 두 번째는 unsigned `r0 / 8`에 해당하는 shift 결과를 가산
- 세 번째는 sign을 유지하는 right shift 결과를 가산
- 음수의 `ASR`은 음의 무한대 방향으로 내림하므로 C signed division의 zero 방향 절삭과 항상 같지는 않음.
- `MOV r2, #9`와 `MUL r1, r0, r2`를 shifted `ADD` 하나로 줄일 수 있는 예
