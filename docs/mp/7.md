# 7. ARM Instruction Set Architecture III

## Topics

- Single 및 multiple memory access와 addressing mode
- Branch, comparison 및 conditional execution

## Load-Modify-Store

- 메모리의 `x = x + 1`을 구현하는 기본 순서
- `r1`은 변수 `x`의 주소를 보관한 상태

```asm
LDR r0, [r1]
ADD r0, r0, #1
STR r0, [r1]
```

- Memory의 값을 load한 후 register에서 수정하고 다시 store함.

## Load and Store Instructions

- `LDR rt, [rs]`는 `rs`의 주소에서 읽어 `rt`에 저장
- `STR rt, [rs]`는 `rt`의 값을 `rs`의 주소에 기록
- `rs = 0x08200004`라면 해당 위치의 word 접근

| 명령어 | 전송 크기 | Register 처리 |
| --- | --- | --- |
| `LDR` | `32` bits | Word 전체 load |
| `LDRB` | `8` bits | Zero extension |
| `LDRH` | `16` bits | Zero extension |
| `LDRSB` | `8` bits | Sign extension |
| `LDRSH` | `16` bits | Sign extension |
| `STR` | `32` bits | Word 전체 store |
| `STRB` | `8` bits | Register 하위 byte만 store |
| `STRH` | `16` bits | Register 하위 halfword만 store |

- Store에는 signed/unsigned extension의 구별이 없으며 저장할 하위 bit만 사용함.

## Load Size and Sign Extension

- Little endian 메모리의 연속 byte가 낮은 주소부터 `0xE1`, `0xE3`, `0x65`, `0x87`인 예
- `r0`가 첫 byte 주소를 가리키는 상태

| 명령어 | `r1` 결과 |
| --- | --- |
| `LDRB r1, [r0]` | `0x000000E1` |
| `LDRH r1, [r0]` | `0x0000E3E1` |
| `LDR r1, [r0]` | `0x8765E3E1` |
| `LDRSB r1, [r0]` | `0xFFFFFFE1` |
| `LDRSH r1, [r0]` | `0xFFFFE3E1` |

- Byte는 bit `7`, halfword는 bit `15`가 sign extension 기준
- 각 load는 `r0`가 가리키는 동일한 byte 배열의 시작 위치에서 수행함.

## Addressing Modes

- Effective address는 base register와 offset으로 계산
- Offset은 immediate 또는 register로 구성 가능

```asm
LDR r0, [r1, #8]
LDR r0, [r1, r2]
LDR r0, [r1, r2, LSL #2]
```

- `LDR r0, [r1, r2, LSL #2]`의 effective address는 `r1 + 4 * r2`
- ARM A32의 offset 형식
  - Word 및 unsigned byte는 `12`-bit immediate 또는 선택적으로 shift한 register
  - Halfword 및 signed byte/halfword는 `8`-bit immediate 또는 shift하지 않은 register
- Thumb-2의 offset 범위와 shift 지원은 각 명령어의 encoding에 따라 결정됨.

## Pre-Indexed Addressing

```asm
LDR r1, [r0, #4]
```

- `r0 + 4`에서 읽고 `r0`는 유지
- `r0 = 0x20008000`이면 접근 주소는 `0x20008004`, 실행 후 `r0 = 0x20008000`

## Post-Indexed Addressing

```asm
LDR r1, [r0], #4
```

- 기존 `r0` 주소에서 읽은 뒤 `r0 = r0 + 4`로 write-back
- 초기 `r0 = 0x20008000`이면 접근 주소는 `0x20008000`, 실행 후 `r0 = 0x20008004`

## Pre-Indexed Addressing with Write-Back

```asm
LDR r1, [r0, #4]!
```

- 먼저 `r0 + 4`를 계산해 그 주소에서 읽고 갱신된 주소를 `r0`에 보관
- 초기 `r0 = 0x20008000`이면 접근 주소와 실행 후 `r0` 모두 `0x20008004`

## Load Examples

- 초기 `r0 = 0x20008000`, `r1 = 0x12345678`
- 낮은 주소부터 byte 배열은 `0xEF`, `0xCD`, `0xAB`, `0x89`

| 별도 실행한 명령어 | 결과 |
| --- | --- |
| `LDRH r1, [r0]` | `r1 = 0x0000CDEF` |
| `LDRSB r1, [r0]` | `r1 = 0xFFFFFFEF` |

- `LDRH`는 읽은 halfword를 zero extend하여 `r1` 전체 갱신
- `LDRSB`는 읽은 byte를 sign extend하여 `r1` 전체 갱신

## Store Examples

- 각 예의 초기값은 `r0 = 0x20008000`, `r1 = 0x76543210`
- Little endian에 따라 낮은 주소부터 `0x10`, `0x32`, `0x54`, `0x76` 기록

| 독립적인 명령어 | 기록 시작 주소 | 실행 후 `r0` |
| --- | --- | --- |
| `STR r1, [r0], #4` | `0x20008000` | `0x20008004` |
| `STR r1, [r0, #4]` | `0x20008004` | `0x20008000` |
| `STR r1, [r0, #4]!` | `0x20008004` | `0x20008004` |

- Offset 유무, 접근 시점 및 write-back 여부를 각각 구별하는 예
- 기록한 word 밖의 byte는 유지됨.

## Load and Store Multiple Instructions

- 형식은 `STMxx rn{!}, {register_list}` 및 `LDMxx rn{!}, {register_list}`
- Register list 순서와 관계없이 작은 번호의 register가 낮은 memory 주소에 대응함.
- `!`가 있으면 전체 전송 후 base register 갱신
- `STM`과 `LDM`은 각각 `STMIA`, `LDMIA`와 같은 의미

| 일반 ARM mode | 주소 진행 | `n`개 word의 가장 낮은 주소 | Write-back |
| --- | --- | --- | --- |
| IA | Increment after | `base` | `base + 4*n` |
| IB | Increment before | `base + 4` | `base + 4*n` |
| DA | Decrement after | `base - 4*(n-1)` | `base - 4*n` |
| DB | Decrement before | `base - 4*n` | `base - 4*n` |

- ARM A32는 IA, IB, DA, DB의 네 mode 지원
- Cortex-M3 Thumb-2의 multiple transfer는 IA와 DB 지원
  - 사용 가능한 base register와 register list는 해당 encoding의 제약 적용
- `STMIA r5, {r0, r1, r2}`는 `r5`, `r5+4`, `r5+8`에 각각 `r0`, `r1`, `r2` 저장
- `STMIA r5, {r2, r1, r0}`로 적어도 같은 결과

| `{r3, r1, r7, r2}` 전송의 mode | `r1` 위치 | `r2` 위치 | `r3` 위치 | `r7` 위치 |
| --- | --- | --- | --- | --- |
| IA | `base` | `base+4` | `base+8` | `base+12` |
| IB | `base+4` | `base+8` | `base+12` | `base+16` |
| DA | `base-12` | `base-8` | `base-4` | `base` |
| DB | `base-16` | `base-12` | `base-8` | `base-4` |

- 각 위치의 메모리 값이 base로부터의 offset과 같다면 `LDM` 결과도 표의 offset 순서와 동일
- IA/IB는 ascending, DA/DB는 descending 배치이며 stack의 full/empty 규칙과 조합해 사용 가능

## Load Pseudo-Instruction and Literal Pool

```asm
LDR r3, =0x55555555
LDR r0, =foo
```

- `LDR Rd, =expression`은 상수 또는 symbol 주소를 register에 구성하는 pseudo-instruction
- `LDR Rd, [Rn]`처럼 해당 주소의 내용을 직접 읽는 표기가 아님.
- Assembler가 표현 가능한 경우 move instruction을 사용하고, 그 외에는 literal pool과 PC-relative load 사용 가능

      ┌─────────────────────┐
      │ LDR r3,[pc,offset]  ├────┐
      │ Other instructions  │    │
      │ Branch past pool    │    │
      ├─────────────────────┤    │
      │ .word 0x55555555    │◀───┘
      └─────────────────────┘

- Literal pool은 접근 가능한 거리와 정렬 조건을 만족해야 함.
- Data를 instruction으로 실행하지 않도록 실행 경로 구성 필요

## Branch Instructions

| 명령어 | 대상 | `LR` 갱신 |
| --- | --- | --- |
| `B label` | Label로 직접 branch | 없음 |
| `BL label` | Label로 subroutine call | 다음 명령어의 Thumb 복귀 주소 |
| `BX Rm` | Register의 주소로 branch | 없음 |
| `BLX Rm` | Register의 주소로 call | 다음 명령어의 Thumb 복귀 주소 |

- `BX lr`로 subroutine 복귀
- Branch 이후 새 위치의 instruction으로 pipeline refill 필요
- Cortex-M3의 register branch target은 Thumb state를 표시하는 bit `0` 필요
- ARM subroutine은 `MOV pc, lr` 또는 `BX lr`로 복귀 가능
- Cortex-M exception return은 `LR`의 `EXC_RETURN` 값을 이용해 stack에 저장한 실행 상태 복원

## Condition Codes and Conditional Branches

| Suffix | Branch | 의미 | Flag 조건 |
| --- | --- | --- | --- |
| `EQ` | `BEQ` | Equal | `Z = 1` |
| `NE` | `BNE` | Not equal | `Z = 0` |
| `CS`, `HS` | `BCS`, `BHS` | Unsigned higher or same | `C = 1` |
| `CC`, `LO` | `BCC`, `BLO` | Unsigned lower | `C = 0` |
| `MI` | `BMI` | Negative | `N = 1` |
| `PL` | `BPL` | Positive or zero | `N = 0` |
| `VS` | `BVS` | Overflow | `V = 1` |
| `VC` | `BVC` | No overflow | `V = 0` |
| `HI` | `BHI` | Unsigned higher | `C = 1` and `Z = 0` |
| `LS` | `BLS` | Unsigned lower or same | `C = 0` or `Z = 1` |
| `GE` | `BGE` | Signed greater or equal | `N = V` |
| `LT` | `BLT` | Signed less than | `N != V` |
| `GT` | `BGT` | Signed greater than | `Z = 0` and `N = V` |
| `LE` | `BLE` | Signed less or equal | `Z = 1` or `N != V` |
| `AL` | `B` | Always | 조건 없음 |

- 비교 대상의 signed/unsigned 해석에 따라 서로 다른 condition 선택
- `PL`은 양수뿐 아니라 zero도 포함함.

## Comparison Instructions

| 명령어 | 내부 연산 | 갱신 flag |
| --- | --- | --- |
| `CMP Rn, Op2` | `Rn - Op2` | `N`, `Z`, `C`, `V` |
| `CMN Rn, Op2` | `Rn + Op2` | `N`, `Z`, `C`, `V` |
| `TST Rn, Op2` | `Rn & Op2` | `N`, `Z`, shifter에 따른 `C` |
| `TEQ Rn, Op2` | `Rn ^ Op2` | `N`, `Z`, shifter에 따른 `C` |

- 연산 결과는 저장하지 않고 flag만 갱신하므로 destination과 `S` suffix 불필요
- `CMP r0, r1`은 `r0`를 보존하지만 `SUBS r0, r0, r1`은 결과까지 저장

## If-Then Statement

- Signed `a < 0`이면 `a = -a`, 이후 `x`를 한 번 증가시키는 예
- `r1 = a`, `r2 = x`

```asm
      CMP r1, #0
      BGE endif
      RSB r1, r1, #0
endif:
      ADD r2, r2, #1
```

- `RSB`는 operand 순서를 반대로 한 subtraction
- 최소 signed 정수의 절댓값은 같은 signed 폭에 표현할 수 없다는 범위 제한 존재

## Compound Boolean Expression with Branches

- Signed 조건 `x <= 20 || x >= 25`가 참이면 `a = 1`
- `r0 = x`, `r1 = a`

```asm
      CMP r0, #20
      BLE then
      CMP r0, #25
      BLT endif
then:
      MOV r1, #1
endif:
```

- 첫 조건이 참이면 두 번째 비교를 생략하는 short-circuit 구조

## If-Then-Else

- `a == 1`이면 `b = 3`, 아니면 `b = 4`
- `r1 = a`, `r2 = b`

```asm
      CMP r1, #1
      BNE else
      MOV r2, #3
      B endif
else:
      MOV r2, #4
endif:
```

- Then 경로 끝에서 branch하지 않으면 else까지 실행되는 문제 발생

## For Loop

- `i = 0`부터 `i < 10`인 동안 `sum += i`를 수행하는 반복문
- `r0 = i`, `r1 = sum`

```asm
      MOV r0, #0
      MOV r1, #0
loop:
      CMP r0, #10
      BGE endloop
      ADD r1, r1, r0
      ADD r0, r0, #1
      B loop
endloop:
```

- 종료 결과는 `i = 10`, `sum = 45`

## Conditional Execution

- 명령어에 condition suffix를 붙여 flag가 조건을 만족할 때만 실행
  - `ADDEQ`는 `Z = 1`일 때 덧셈
  - `ADDNE`는 `Z = 0`일 때 덧셈
  - `ADDHS`는 `C = 1`일 때 덧셈
- ARM A32는 instruction 내부의 condition field 사용
- Thumb-2는 `IT`가 뒤따르는 instruction의 실행 조건 지정

```asm
@ If a < 0, negate a, then increment x
CMP r1, #0
IT LT
RSBLT r1, r1, #0
ADD r2, r2, #1

@ If a <= 0, y = -1, otherwise y = 1
CMP r0, #0
ITE LE
MOVLE r1, #-1
MOVGT r1, #1
```

- 조건부 instruction은 실행 시점의 condition flag로 실행 여부 결정

## Compound Boolean Expression with Conditions

- `x <= 20 || x >= 25`이면 `a = 1`인 예

```asm
CMP r0, #20
IT LE
MOVLE r1, #1
IT GT
CMPGT r0, #25
IT GE
MOVGE r1, #1
```

- 첫 비교가 `x <= 20`이면 두 번째 비교 생략
- 이 경우 마지막 `GE`가 실행되더라도 같은 값 `1`을 다시 쓰므로 최종 결과 동일
- `x <= 20 || y >= 25`가 참이면 `a`를 한 번 증가
  - 첫 조건이 참이면 두 번째 비교를 건너뛰고 공통 increment 경로로 이동
  - 첫 조건이 거짓이면 두 번째 조건을 확인한 뒤 같은 경로로 이동

```asm
@ r0 = x, r1 = a, r2 = y
      CMP r0, #20
      BLE increment
      CMP r2, #25
      BLT done
increment:
      ADD r1, r1, #1
done:
```

- `a == 1 || a == 7 || a == 11`이면 `y = 1`, 아니면 `y = -1`인 예

```asm
CMP r0, #1
IT NE
CMPNE r0, #7
IT NE
CMPNE r0, #11
ITE EQ
MOVEQ r1, #1
MOVNE r1, #-1
```

- 일치한 경우 `Z = 1`을 유지하며 이후 비교를 건너뛰는 방식

## IT Instruction

- 형식은 `IT{x{y{z}}} cond`, 뒤따르는 `1–4`개 명령어의 조건 제어
- 첫 명령어는 `cond`, 추가 위치의 `T`는 같은 조건, `E`는 반대 조건
- `ITTTE`는 Then, Then, Then, Else의 네 명령어 제어
- 명령어 encoding 안의 여유 bit가 부족한 Thumb에서 conditional execution을 제공하는 방식

```asm
IT EQ
ANDEQ r0, r0, r1

ITET NE
ANDNE r0, r0, r1
ADDEQ r2, r2, #1
MOVNE r2, r3
```

- IT block 안의 flag 갱신은 instruction의 `S` suffix와 encoding에 따라 결정됨.
- Flag 갱신 시 뒤따르는 조건부 instruction도 변경된 flag 사용
- Thumb mode에서 implicit IT 생성을 지원하도록 assembler를 설정하면 condition suffix에 맞춰 IT를 자동 생성
  - ARM A32 mode는 각 instruction에 condition field가 있으므로 IT 불필요
