# 4. Memory Systems

## Topics

- Memory map, memory attribute와 접근 권한
- MPU, bit-banding, unaligned transfer 및 endianness

## Logic View of Memory

- 소프트웨어 관점의 메모리는 주소로 접근하는 byte 배열
- `1 byte = 8 bits`, `1 halfword = 16 bits`, `1 word = 32 bits`
- 여러 byte로 구성된 값의 주소는 그중 가장 낮은 byte 주소
- Word는 보통 `4`의 배수 주소, halfword는 `2`의 배수 주소로 정렬

| 주소 | 저장된 byte |
| --- | --- |
| `0x20000000` | `0b10010100` |
| `0x20000001` | `0b00010010` |
| `0x20000002` | `0b10001111` |
| `0x20000003` | `0b01100001` |
| `0x20000004` | `0b10000100` |
| `0x20000005` | `0b11100010` |
| `0x20000006` | `0b00100101` |
| `0x20000007` | `0b01110010` |

- 위 영역의 aligned word 주소는 `0x20000000`, `0x20000004`
- Aligned halfword 주소는 `0x20000000`, `0x20000002`, `0x20000004`, `0x20000006`
- Word를 `0x20000002`에서 읽거나 halfword를 `0x20000001`에서 읽으면 unaligned access

## Memory Map

- 메모리, system resource 및 I/O peripheral의 주소 공간 배치
- Cortex-M3의 `32`-bit 주소 공간은 `4 GiB`
  - 실제 구현된 물리 메모리의 크기는 microcontroller 제품에 따라 결정됨.
- 고정된 기본 배치와 공통 system register 주소로 제품 간 소프트웨어 이식 지원

| 영역 | 주소 범위 | 크기 |
| --- | --- | --- |
| Code | `0x00000000–0x1FFFFFFF` | `512 MiB` |
| SRAM | `0x20000000–0x3FFFFFFF` | `512 MiB` |
| Peripheral | `0x40000000–0x5FFFFFFF` | `512 MiB` |
| External RAM | `0x60000000–0x9FFFFFFF` | `1 GiB` |
| External device | `0xA0000000–0xDFFFFFFF` | `1 GiB` |
| System | `0xE0000000–0xFFFFFFFF` | `512 MiB` |

| System 내부 영역 | 시작 주소 | 용도 |
| --- | --- | --- |
| ITM | `0xE0000000` | Instrumentation trace |
| DWT | `0xE0001000` | Data watchpoint와 trace |
| FPB | `0xE0002000` | Flash patch와 breakpoint |
| SCS | `0xE000E000` | NVIC, system control 및 MPU register |
| Internal PPB reserved | `0xE000F000` | 내부 system 영역 |
| TPIU | `0xE0040000` | Trace 출력 interface |
| ETM | `0xE0041000` | Instruction trace |
| External PPB | `0xE0042000` | 외부 private peripheral |
| ROM table | `0xE00FF000` | Debug component 탐색 |
| Vendor specific | `0xE0100000` | 제조사 정의 영역 |

- SRAM과 peripheral 각각의 첫 `1 MiB`에 bit-band region, 별도의 `32 MiB` 영역에 alias 배치

## Memory Access Attributes

| Attribute | 의미 |
| --- | --- |
| Bufferable | Write buffer가 쓰기를 진행하는 동안 processor의 다음 명령 실행 가능 |
| Cacheable | 읽은 데이터를 cache에 보관해 이후 접근 가속 가능 |
| Executable | Instruction fetch 및 실행 허용 |
| Shareable | 여러 bus master가 공유하는 영역으로 일관성 처리 필요 |

- MPU가 존재하고 활성화되어 있으면 영역 설정으로 기본 attribute 변경 가능
- Cacheable 영역은 메모리 시스템에 cache가 구현되어 있을 때 해당 cache 사용 가능

| 영역 | Cacheable | Executable | Bufferable |
| --- | --- | --- | --- |
| Code | 가능 | 가능 | 가능 |
| SRAM | 가능 | 가능 | 가능 |
| Peripheral | 불가 | 불가 | 가능 |
| External RAM | 가능 | 가능 | 가능 |
| External device | 불가 | 불가 | 불가 |
| System PPB | 불가 | 불가 | 불가 |
| Vendor specific | 불가 | 불가 | 가능 |

## Default Memory Access Permissions

- MPU가 없거나 비활성화된 경우 기본 접근 권한 적용
- 활성 MPU 사용 시 영역의 접근 권한 검사 후 위반 접근에 fault 발생

| 영역 | Unprivileged 접근 |
| --- | --- |
| Code, SRAM, peripheral, external RAM | 기본 접근 허용 |
| ITM `0xE0000000–0xE0000FFF` | 읽기 허용, 쓰기는 user access가 허용된 stimulus port를 제외하고 무시 |
| DWT `0xE0001000–0xE0001FFF` | 차단 |
| FPB `0xE0002000–0xE0003FFF` | 차단 |
| SCS `0xE000E000–0xE000EFFF` | 차단 |
| Internal PPB `0xE000F000–0xE003FFFF` | 차단 |
| TPIU `0xE0040000–0xE0040FFF` | 차단 |
| ETM `0xE0041000–0xE0041FFF` | 차단 |
| Vendor specific `0xE0100000–0xFFFFFFFF` | 기본 permission에서 접근 허용 |

- 접근하려는 주소에는 실제 memory 또는 peripheral이 구현되어 있어야 함.
- Instruction fetch에는 executable attribute도 필요
- PPB의 차단된 접근은 BusFault의 원인

## Memory Protection Unit

- 메모리 및 I/O 접근이 허용되는지 영역별로 검사하는 장치
- Fetch, read, write 및 privileged/unprivileged 권한을 구별함.
- Cacheability, shareability 등의 attribute도 설정 가능
- MPU는 processor에 따라 `8–16`개 region을 지원하며 Cortex-M3는 선택적 `8`-region MPU 제공
- 위반 시 MemManage fault 발생 가능

| Privileged | Unprivileged | 의미 |
| --- | --- | --- |
| No access | No access | 모든 접근 차단 |
| RO | No access | Privileged 읽기만 허용 |
| RO | RO | 두 수준 모두 읽기만 허용 |
| RW | No access | Privileged 읽기와 쓰기만 허용 |
| RW | RO | User 쓰기 차단 |
| RW | RW | 두 수준 모두 읽기와 쓰기 허용 |

- Armv7-M은 region의 중첩을 허용하며 겹친 위치에는 가장 큰 region number의 설정 적용
- 예를 들어 `R0` 전체를 privileged 전용으로 두고 내부 `R2`를 user RW로 설정하면 중첩된 내부는 `R2`의 권한 적용
- 다시 더 높은 번호의 RO region을 겹치면 해당 부분은 RO로 제한 가능

## Bit-Band Operations

- 하나의 bit를 alias 주소의 word load/store로 접근하는 기능
- Bus matrix가 alias 주소를 원래 주소와 bit 위치로 변환함.

| 대상 | Bit-band region | Alias region |
| --- | --- | --- |
| SRAM | `0x20000000–0x200FFFFF` | `0x22000000–0x23FFFFFF` |
| Peripheral | `0x40000000–0x400FFFFF` | `0x42000000–0x43FFFFFF` |

- 원래 `1` byte의 `8`개 bit마다 `4` bytes의 alias word를 할당하므로 `1 MiB`가 `32 MiB`에 대응함.
- $b$는 region base로부터의 byte offset, $k$는 해당 byte의 bit 번호 `0–7`

$$$
\mathrm{alias}=\mathrm{alias\_base}+32b+4k
$$$

| 원본 위치 | SRAM alias | Peripheral alias |
| --- | --- | --- |
| 첫 word의 bit `0` | `0x22000000` | `0x42000000` |
| 첫 word의 bit `1` | `0x22000004` | `0x42000004` |
| 첫 word의 bit `2` | `0x22000008` | `0x42000008` |
| 첫 word의 bit `31` | `0x2200007C` | `0x4200007C` |
| 다음 word의 bit `0` | `0x22000080` | `0x42000080` |
| 마지막 word의 bit `31` | `0x23FFFFFC` | `0x43FFFFFC` |

- Word 기준 bit `31`은 byte offset `3`의 bit `7`로 계산 가능

## Write to Bit-Band Alias

- 주소 `0x20000000`의 bit `2`를 설정하는 두 방법

```asm
@ Ordinary read-modify-write
LDR r0, =0x20000000
LDR r1, [r0]
ORR r1, r1, #4
STR r1, [r0]

@ Bit-band write
LDR r0, =0x22000008
MOV r1, #1
STR r1, [r0]
```

- Alias word에 `1`을 쓰면 대응 bit 설정, `0`을 쓰면 해제
- Hardware 내부에서는 원래 word를 읽고 선택 bit를 수정하여 쓰는 transaction 수행
- Software에서 별도의 read-modify-write를 수행하는 것과 달리 bit 수정의 atomicity 제공

## Read from the Bit-Band Alias

```asm
@ Ordinary bit extraction
LDR r0, =0x20000000
LDR r1, [r0]
UBFX r1, r1, #2, #1

@ Bit-band read
LDR r0, =0x22000008
LDR r1, [r0]
```

- 선택한 bit가 반환 word의 bit `0`에 위치하며 결과는 `0` 또는 `1`
- Hardware가 원본을 읽고 필요한 bit를 추출하므로 software shift 및 mask 불필요

## Advantages of Bit-Band Operations

- Bit 조작의 명령어 수 감소 및 상황에 따른 속도 향상
- 공유 word의 서로 다른 bit를 수정할 때 lost update 방지

| 순서 | 일반 read-modify-write | 공유 값 |
| --- | --- | --- |
| `1` | Main이 기존 값 읽기 | `0` |
| `2` | Handler가 bit `0` 설정 | `1` |
| `3` | Main이 과거에 읽은 `0`에서 bit `1` 설정 후 쓰기 | `2` |

- 원하는 값은 `3`이지만 main의 오래된 값 쓰기로 handler의 변경 소실
- Bit-band write는 원본 word의 수정 구간을 분리할 수 없게 처리하여 다른 bit의 변경 보존
- Atomicity는 한 번의 bit-band write에 적용되며 여러 transaction으로 구성한 연산은 별도 동기화 필요

## Bit-Band Operations in C

- 대부분의 C compiler는 bit-band operation의 직접적인 언어 지원을 제공하지 않음.
  - 원래 주소와 bit-band alias 주소를 각각 선언하여 접근
  - Memory-mapped register는 `volatile` pointer로 참조

```c
#include <stdint.h>

#define DEVICE_REG0 (*(volatile uint32_t *)0x40000000u)
#define DEVICE_REG0_BIT0 (*(volatile uint32_t *)0x42000000u)
#define DEVICE_REG0_BIT1 (*(volatile uint32_t *)0x42000004u)

DEVICE_REG0 = 0xABu;
DEVICE_REG0 = DEVICE_REG0 | 0x2u;
DEVICE_REG0_BIT1 = 1u;
```

- 주소와 bit 번호를 받는 macro로 같은 접근 일반화

```c
#define BITBAND(addr, bitnum) \
    (((uintptr_t)(addr) & 0xF0000000u) + 0x02000000u + \
     (((uintptr_t)(addr) & 0x000FFFFFu) << 5) + \
     ((uintptr_t)(bitnum) << 2))
#define MEM_ADDR(addr) (*(volatile uint32_t *)(uintptr_t)(addr))
#define DEVICE_REG0_ADDR 0x40000000u

MEM_ADDR(DEVICE_REG0_ADDR) = 0xABu;
MEM_ADDR(BITBAND(DEVICE_REG0_ADDR, 1)) = 1u;
```

- `BITBAND`는 SRAM 및 peripheral의 bit-band 주소와 bit 번호를 alias 주소로 변환
- `MEM_ADDR`는 정수 주소를 `volatile uint32_t` lvalue로 변환

## Unaligned Transfers

- Cortex-M3는 일부 single load/store의 unaligned access 지원
- 자연 정렬은 값의 크기의 배수 주소에 배치하는 방식
- Packed structure는 padding을 줄이는 대신 unaligned field를 만들 수 있음.

```c
struct Example {
    long a;
    char b;
    long c;
    char d[3];
    short e;
    long f;
    short g;
    char h;
    short i;
    int j;
};
```

- `long`과 `int`는 `4` bytes, `short`는 `2` bytes인 환경 가정

| Field | 자연 정렬 offset | Packed offset |
| --- | --- | --- |
| `a` | `0` | `0` |
| `b` | `4` | `4` |
| `c` | `8` | `5` |
| `d` | `12` | `9` |
| `e` | `16` | `12` |
| `f` | `20` | `14` |
| `g` | `24` | `18` |
| `h` | `26` | `20` |
| `i` | `28` | `21` |
| `j` | `32` | `23` |
| 전체 크기 | `36` bytes | `27` bytes |

- Packed 선언은 structure 끝의 `__attribute__((__packed__))` 사용
- Bus interface가 unaligned access를 여러 aligned transfer로 변환
  - Application에서는 하나의 data access로 사용
  - 분할된 transfer로 인해 더 많은 clock cycle 소요
- `LDM`/`STM`, `PUSH`/`POP`, exclusive access 및 bit-band access는 정렬 필요
- Unaligned 지원 및 fault 여부는 명령어, memory type과 system 설정에 의존함.

| `32`-bit bus에서 word 시작 주소 | 데이터가 차지하는 byte 위치 |
| --- | --- |
| `N` | `N–N+3`, aligned |
| `N+1` | `N+1–N+4`, bus word 경계 통과 |
| `N+2` | `N+2–N+5`, bus word 경계 통과 |
| `N+3` | `N+3–N+6`, bus word 경계 통과 |

- `N`은 `4`의 배수인 aligned bus word의 시작 주소
- Halfword는 `N` 또는 `N+2`에서 aligned, `N+1` 또는 `N+3`에서 unaligned
- `N+1`의 halfword는 한 bus word 안에 들어가도 자연 정렬 조건은 만족하지 않음.

## Endian Mode

- Little endian은 낮은 주소에 least significant byte 저장
- Big endian은 낮은 주소에 most significant byte 저장
- Cortex-M3는 little endian과 big endian 지원
  - 권장 구성은 little endian
  - 지원 가능한 memory 구성은 bus 연결, memory controller 및 peripheral 설계에 따라 결정됨.
  - 소프트웨어 개발 전 microcontroller datasheet의 endian 지원 확인 필요

| 주소 | `0x12345678`의 little endian | `0x12345678`의 big endian |
| --- | --- | --- |
| `A` | `0x78` | `0x12` |
| `A+1` | `0x56` | `0x34` |
| `A+2` | `0x34` | `0x56` |
| `A+3` | `0x12` | `0x78` |
