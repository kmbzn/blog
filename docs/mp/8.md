# 8. ARM Subroutines

## Topics

- Subroutine call과 calling convention
- Stack을 이용한 register 보존, nested call 및 recursion

## Subroutine Calls

- Subroutine은 function 또는 procedure라고도 부르는 재사용 가능한 실행 단위
- 기본 모델은 single-entry, single-exit이며 완료 후 caller로 복귀
- Caller는 호출하는 쪽, callee는 호출된 subroutine
- `BL label`은 다음 명령어의 복귀 주소를 `LR`에 저장하고 label로 이동
- `BX lr`은 `LR`에 저장된 복귀 주소로 branch하여 caller의 다음 instruction 실행
- Label은 assembler와 linker가 실제 주소로 해결함.
- Cortex-M의 `LR` 복귀 주소에는 Thumb state를 나타내는 bit `0` 포함
- Stack에 저장한 복귀 주소는 `POP {pc}`로 복구하며 복귀 가능

## ARM Calling Convention

| Register | 주 용도 | 보존 책임 |
| --- | --- | --- |
| `r0` | 첫 인수 및 기본 반환값 | Caller-saved |
| `r1` | 두 번째 인수 및 다중 register 결과 일부 | Caller-saved |
| `r2` | 세 번째 인수 | Caller-saved |
| `r3` | 네 번째 인수 | Caller-saved |
| `r4–r8` | Local variable 등 지속 상태 | Callee-saved |
| `r9` | Platform-specific register 또는 추가 variable register | Platform ABI에 따름. |
| `r10–r11` | 지속 상태와 frame 관련 용도 | Callee-saved |
| `r12`, `IP` | 호출 사이의 scratch, veneer 임시 작업 | Caller-saved |
| `r13`, `SP` | Stack pointer | 복귀 시 진입 상태로 복원 |
| `r14`, `LR` | 복귀 주소 | Nested call 전 기존 복귀 주소 보존 필요 |
| `r15`, `PC` | 실행 흐름 | 일반 data 보존 대상이 아님. |

- Caller-saved는 caller가 복귀 후에도 필요한 값만 직접 보존하는 register
- Callee-saved는 callee가 변경한다면 원래 값을 저장하고 복귀 전에 복구해야 하는 register
- Caller는 호출 이후에도 사용할 caller-saved 값만 호출 전에 보존
- `r9`의 사용과 보존 규칙은 platform ABI에서 결정함.
- Public function interface에서 stack의 `8`-byte 정렬 유지 필요

## Passing Arguments via Registers

- 기본적인 `32`-bit 인수 네 개는 `r0–r3`으로 전달
- 추가 인수는 caller가 stack에 배치하고 호출 후 정리
- `64`-bit 인수는 정렬된 register 쌍 사용
  - 첫 인수는 하위 `r0`, 상위 `r1`
  - 두 번째 인수는 하위 `r2`, 상위 `r3`
- Register 전체를 사용하는 `128`-bit 인수는 낮은 부분부터 `r0`, `r1`, `r2`, `r3` 배치
- `32`-bit 기본 반환값은 `r0`, `64`-bit 기본 반환값은 하위 `r0`와 상위 `r1`
- `128`-bit 값의 반환 방식은 data type과 ABI에 따라 달라짐. 일반적인 큰 structure는 caller가 제공한 결과 메모리 사용 가능

## Sum of Squares Example

- 두 정수의 제곱합을 반환하는 subroutine `SSQ`
- 계산은 `x*x + y*y`, 인수는 `r0 = 3`, `r1 = 4`

```asm
      MOV r0, #3
      MOV r1, #4
      BL SSQ
      MOV r2, r0
      B ENDL
SSQ:
      MUL r2, r0, r0
      MUL r3, r1, r1
      ADD r2, r2, r3
      MOV r0, r2
      BX lr
ENDL:
      B ENDL
```

| 실행 지점 | 상태 변화 |
| --- | --- |
| 인수 준비 | `r0 = 3`, `r1 = 4` |
| `BL SSQ` | 복귀 주소 저장 후 `SSQ` 진입 |
| 첫 `MUL` | `r2 = 9` |
| 두 번째 `MUL` | `r3 = 16` |
| `ADD` | `r2 = 25` |
| `MOV r0, r2` | 반환값 `r0 = 25` |
| `BX lr` | Caller의 `MOV r2, r0`로 복귀 |
| Caller의 결과 복사 | 최종 `r2 = 25` |

- `r2`, `r3`는 caller-saved이므로 callee 내부에서 임시값으로 사용 가능
- Call instruction 주소 `0x08000130`, 다음 instruction 주소 `0x08000134` 예에서 실제 Thumb `LR` 값은 `0x08000135`
- 복귀 instruction의 주소는 짝수이며 `LR`에는 Thumb state를 표시하는 bit `0` 포함

## Instruction Width and Fetch

- Thumb instruction의 길이에 따라 다음 instruction 주소는 `2` 또는 `4` 증가
- 첫 halfword의 상위 `5` bits가 `11101`, `11110`, `11111`이면 `32`-bit instruction 시작
- `32`-bit instruction memory에서 한 번의 fetch로 `4` bytes 수신
  - 두 개의 `16`-bit instruction 또는 하나의 `32`-bit instruction에 해당
- Instruction operand로 읽는 `PC` 값은 현재 instruction 주소에 `4`를 더한 값

## Preserving the Environment with a Stack

- Stack은 마지막에 넣은 값을 먼저 꺼내는 LIFO 자료구조
- Top은 가장 최근에 넣은 item의 위치
- `PUSH`는 item 추가, `POP`은 top item 제거 및 읽기
- Call마다 register와 return address를 별도로 보관하는 데 활용

## Stack Growth Conventions

| 구분 | 의미 |
| --- | --- |
| Ascending | Push할 때 높은 주소 방향으로 성장 |
| Descending | Push할 때 낮은 주소 방향으로 성장 |
| Full | `SP`가 마지막으로 저장한 item을 지칭 |
| Empty | `SP`가 다음에 저장할 빈 위치를 지칭 |

- 성장 방향과 `SP`가 지칭하는 위치는 독립적인 두 기준
- 조합에 따라 full ascending, empty ascending, full descending, empty descending 구성 가능

## Cortex-M Full Descending Stack

- Cortex-M은 full descending stack 사용
- Single word push는 먼저 `SP = SP - 4`, 이후 해당 주소에 저장
- Single word pop은 현재 `SP`에서 읽고 `SP = SP + 4`
- 여러 register를 한 번에 push/pop하면 register 번호순으로 메모리에 대응

| 동작 | 동등한 multiple transfer | 주소 변화 |
| --- | --- | --- |
| `PUSH {register_list}` | `STMDB sp!, {register_list}` | 먼저 낮은 주소 공간 확보 |
| `POP {register_list}` | `LDMIA sp!, {register_list}` | 읽은 뒤 높은 주소로 복구 |

- `PUSH {r6, r7, r8}`과 `PUSH {r8, r7, r6}`는 같은 동작
- 이를 single push로 나누면 `r8`, `r7`, `r6` 순서로 push해야 같은 배치
- 대응하는 single pop 순서는 `r6`, `r7`, `r8`
- `{r3, r1, r7, r2}`를 한 번에 push하면 낮은 주소부터 `r1`, `r2`, `r3`, `r7`

      High address
      ┌──────────────────┐
      │ Previous content │
      ├──────────────────┤
      │ Saved r7         │
      ├──────────────────┤
      │ Saved r3         │
      ├──────────────────┤
      │ Saved r2         │
      ├──────────────────┤
      │ Saved r1         ◀─── SP
      └──────────────────┘
      Low address

- Register list의 표기 순서를 바꾸는 방식으로 값을 swap할 수는 없음.

## Swapping Registers with the Stack

- 초기 `r1 = 0x11111111`, `r2 = 0x22222222`, `SP = 0x20000200`

```asm
PUSH {r1}
PUSH {r2}
POP {r1}
POP {r2}
```

| 명령어 | 실행 후 `SP` | 주요 변화 |
| --- | --- | --- |
| 첫 push | `0x200001FC` | 해당 주소에 `0x11111111` 저장 |
| 두 번째 push | `0x200001F8` | 해당 주소에 `0x22222222` 저장 |
| 첫 pop | `0x200001FC` | `r1 = 0x22222222` |
| 두 번째 pop | `0x20000200` | `r2 = 0x11111111` |

- 두 single push와 두 single pop의 순서가 교환을 만드는 핵심
- Pop 이후 메모리의 과거 byte가 지워지는 것은 아니며 stack의 유효 범위만 줄어듦.

## Preserving Callee-Saved Registers

- Caller의 `r4 = 100`을 callee가 임시로 `10`으로 변경하는 예

```asm
caller:
      MOV r4, #100
      BL foo
      ADD r4, r4, #1
      B done
foo:
      PUSH {r4}
      MOV r4, #10
      POP {r4}
      BX lr
done:
      B done
```

- `foo`는 `r4`를 임시로 사용한 뒤 저장해 둔 원래 값 복구
- 복귀 전 `r4`를 복구하므로 caller의 덧셈 결과는 `101`
- 저장과 복구를 생략하면 callee-saved 규약 위반 및 결과 `11`

## Nested Subroutine Calls

- `BL`은 매번 `LR`을 덮어쓰므로 다른 subroutine을 호출하는 함수는 자신의 복귀 주소 보존 필요
- 보존하지 않으면 마지막 nested call의 다음 instruction으로 잘못 복귀할 수 있음.
- 기본 순서는 함수 진입 시 `LR` 저장, nested call 실행, 복귀 전에 저장값 복구
- `PROC`는 특정 assembler의 procedure 표시이며 실제 call이나 stack 저장을 수행하는 instruction이 아님.

## Fourth Power Example

- `QUAD`가 `SQ`를 두 번 호출하여 입력의 네제곱 계산
- Caller의 인수는 `r0`, `SQ`의 결과도 `r0`로 전달

```asm
      MOV r0, #2
      BL QUAD
      B ENDL
SQ:
      MUL r0, r0, r0
      BX lr
QUAD:
      PUSH {lr}
      BL SQ
      BL SQ
      POP {lr}
      BX lr
ENDL:
      B ENDL
```

| 단계 | `r0` | `SP` 변화 | 복귀 상태 |
| --- | --- | --- | --- |
| Caller에서 인수 준비 | `2` | 초기 `0x20000200` | `BL QUAD`가 caller 복귀 주소 기록 |
| `QUAD` 진입 후 push | `2` | `0x200001FC` | Caller 복귀 주소를 stack에 보관 |
| 첫 `BL SQ` 및 복귀 | `4` | 유지 | `LR`은 두 번째 `BL SQ` 위치를 지칭 |
| 두 번째 `BL SQ` 및 복귀 | `16` | 유지 | `LR`은 `POP` 위치를 지칭 |
| `POP {lr}` | `16` | `0x20000200` | 원래 caller 복귀 주소 복구 |
| `BX lr` | `16` | 유지 | Caller로 복귀 |

- Caller 복귀 instruction 주소 `0x08000140`에 대응하는 실제 Thumb return value는 `0x08000141`
- `PUSH {lr}`만 수행하면 stack이 `4` bytes 감소하므로 nested call의 public interface에서 `8`-byte 정렬을 유지하지 못함.
- Public interface의 `8`-byte 정렬을 유지하는 저장·복구 쌍은 `PUSH {r4, lr}`와 `POP {r4, pc}`
- `POP {lr}`는 `LR`을 지원하는 `32`-bit Thumb encoding 사용

## Initializing the Stack Pointer

- Stack을 사용하기 전에 유효한 RAM 영역과 초기 stack top 필요
- 일반적인 `startup.s`와 linker 설정에서 stack 공간 정의
- `LDR sp, =__stack_top__`으로 `SP`를 stack top 주소로 초기화 가능
- Cortex-M reset은 vector table의 첫 word를 읽어 `MSP`를 자동 초기화함.
- Full descending stack의 빈 초기 `SP`는 예약 영역의 마지막 byte 다음 주소로 설정 가능

## Stack and Recursive Functions

- Recursive function은 자기 자신을 더 작은 문제에 호출하는 함수
- 같은 종류의 subproblem으로 분할하고, subproblem을 해결한 뒤 결과 결합
- 종료 조건인 base case가 필요하며 그렇지 않으면 무한 recursion과 stack 고갈 가능
- 호출별로 다른 argument, local state 및 return address를 stack frame에 보존

## Defining Factorial

- Factorial은 `1`부터 $n$까지의 정수 곱

$$$
n! = \begin{cases}
1 & n=0 \\
n\,(n-1)! & n\geq 1
\end{cases}
$$$

- $6! = 6\times5! = 6\times5\times4! = 720$
- 입력 범위는 $n\geq0$

```c
int Factorial(int n) {
      if (n < 2)
          return 1;
      return n * Factorial(n - 1);
}
```

- `n < 2`에서 base case 반환, 나머지는 recursive result에 원래 `n`을 곱함.
- 실제 정수형으로 표현할 수 있는 결과 범위를 넘으면 overflow 문제 발생

## Recursive Factorial in Assembly

- `r0`에 argument와 반환값, `r4`에 현재 호출의 원래 argument 보관
- 각 호출에서 `r4`와 `LR`을 함께 저장하므로 frame당 `8` bytes 사용

```asm
.global __main
__main:
      MOV r0, #3
      BL factorial
stop:
      B stop
factorial:
      PUSH {r4, lr}
      MOV r4, r0
      CMP r4, #2
      BGE NZ
      MOV r0, #1
loop:
      POP {r4, pc}
NZ:
      SUB r0, r4, #1
      BL factorial
      MUL r0, r4, r0
      B loop
```

- `r0`는 재귀 반환값에 의해 바뀌므로 원래 `n`을 callee-saved인 `r4`에 보관해야 함.
- 다음 recursive call도 `r4`를 사용하지만 자신의 frame에서 저장·복구하므로 caller의 `r4` 유지
- `POP {r4, pc}`는 원래 `r4` 복구와 saved `LR`에 의한 복귀를 함께 수행
- `loop`는 저장한 상태를 복구하고 caller로 복귀하는 공통 경로

| 실행 단계 | 현재 `r4` | 반환값 `r0` | 실행 후 `SP` |
| --- | --- | --- | --- |
| 초기 caller | `0` 가정 | 인수 `3` | `0x20000600` |
| `factorial(3)` frame 생성 | `3` | `3` | `0x200005F8` |
| `factorial(2)` frame 생성 | `2` | `2` | `0x200005F0` |
| `factorial(1)` frame 생성 | `1` | `1` | `0x200005E8` |
| Base case 복귀 | `2`로 복구 | `1` | `0x200005F0` |
| `2 * 1` 계산 후 복귀 | `3`으로 복구 | `2` | `0x200005F8` |
| `3 * 2` 계산 후 복귀 | 최초 `0`으로 복구 | `6` | `0x20000600` |

- `factorial(1)` 진입 직후에는 세 호출의 frame이 stack에 존재
- 각 frame에 저장하는 복귀 주소에는 Thumb state를 표시하는 bit `0` 포함

      High address
      ┌────────────┬──────────────────┐
      │ 0x200005FC │ Caller return    │
      ├────────────┼──────────────────┤
      │ 0x200005F8 │ Saved r4 = 0     │
      ├────────────┼──────────────────┤
      │ 0x200005F4 │ Recursive return │
      ├────────────┼──────────────────┤
      │ 0x200005F0 │ Saved r4 = 3     │
      ├────────────┼──────────────────┤
      │ 0x200005EC │ Recursive return │
      ├────────────┼──────────────────┤
      │ 0x200005E8 │ Saved r4 = 2     ◀─── SP
      └────────────┴──────────────────┘
      Low address

- `factorial(3)`의 최대 추가 stack 사용량은 `24` bytes
- Caller의 복귀 instruction은 `0x08000134`, recursive call 뒤 multiply는 `0x08000148`
- Stack에 저장되는 실제 Thumb 복귀 값은 각각 `0x08000135`, `0x08000149`
- 최종 결과는 `r0 = 6`, 초기 `SP` 및 callee-saved `r4` 복원
