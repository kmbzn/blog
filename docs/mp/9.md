## ARMv7-M Interrupt Handling

- 하나의 Non-Maskable Interrupt인 NMI 지원
- 최대 `511`개의 exception 번호 공간과 최대 `496`개의 external interrupt 지원
  - Internal exception용 `15`개 번호 포함
  - Mask 가능한 interrupt는 필요에 따라 처리 차단 가능
  - 실제 지원하는 interrupt 수는 구현 시 선택
- Nested Vectored Interrupt Controller인 NVIC는 processor core와 긴밀하게 결합된 interrupt controller
  - Peripheral의 IRQ와 NMI 요청, core의 system exception 처리 연결
  - SysTick timer는 core 내부의 system exception 발생원

## Interrupt Service Routine Vector Table

- 첫 entry는 초기 Main Stack Pointer 값
- 나머지 entry는 exception 및 interrupt handler의 주소
  - Thumb state를 나타내도록 주소의 최하위 bit는 항상 `1`
- Vector table은 다른 주소로 relocation 가능
  - Vector Table Offset Register인 `VTOR` 사용
  - Core boot를 위해 주소 `0x0`에서 최소한의 초기 vector entry 접근 필요
- C code로 vector table 생성 가능
- 아래 주소는 vector table 시작 위치 기준 offset

| Offset | Entry |
| --- | --- |
| `0x00` | Initial Main SP |
| `0x04` | Reset |
| `0x08` | NMI |
| `0x0C` | HardFault |
| `0x10` | MemManage Fault |
| `0x14` | BusFault |
| `0x18` | UsageFault |
| `0x1C–0x28` | Reserved, 네 entry |
| `0x2C` | SVC |
| `0x30` | Debug Monitor |
| `0x34` | Reserved |
| `0x38` | PendSV |
| `0x3C` | SysTick |
| `0x40` | External interrupt `0` |
| `0x40 + 4*N` | External interrupt `N` |

## Interrupt Service Routine Vector Table of Cortex-M Processors

| Exception 번호 | 이름 | Priority | 역할 |
| --- | --- | --- | --- |
| `1` | Reset | `-3`, 최고 | Reset과 startup |
| `2` | NMI | `-2` | Mask 불가능한 interrupt |
| `3` | HardFault | `-1` | 다른 fault handler로 처리할 수 없는 fault |
| `4` | MemManage Fault | 설정 가능 | MPU 위반 또는 허용되지 않은 위치 접근 |
| `5` | BusFault | 설정 가능 | AHB interface의 오류 응답 |
| `6` | UsageFault | 설정 가능 | 프로그램 오류에 의한 exception |
| `11` | SVCall | 설정 가능 | System service call |
| `12` | Debug Monitor | 설정 가능 | Breakpoint, watchpoint 및 외부 debug |
| `14` | PendSV | 설정 가능 | System service를 위한 pend 가능한 요청 |
| `15` | SysTick | 설정 가능 | System tick timer |
| `16` | External interrupt `0` | 설정 가능 | Peripheral interrupt |
| `255` | External interrupt `239` | 설정 가능 | 같은 번호 대응 규칙의 예 |
| `511` | External interrupt `495` | 설정 가능 | ARMv7-M 최대 번호 |

- Reset, NMI, fault는 startup 및 fault 처리, SVCall부터 SysTick까지는 system handler, external interrupt는 사용자 주변 장치 handler에 해당
- External interrupt의 exception 번호는 `IRQn + 16`
- Reserved 번호는 실제 handler에 할당하지 않음.

## Interrupt Handling Process

1. `main()` 실행 중 interrupt signal 발생
2. Processor가 interrupt를 인식하고 현재 실행을 중단한 뒤 `r0–r3`, `r12`, `LR`, `PC`, `xPSR` 자동 stacking
3. Vector table에서 handler 주소를 읽어 `PC`에 반영
4. Interrupt Service Routine인 ISR 실행
5. Interrupt return 시 active 상태를 해제하고 저장한 register를 자동 unstacking
6. 중단된 main program 실행 재개

- SysTick 요청은 vector table의 `SysTick_Handler` 주소를 통해 처리
- 다른 주변 장치도 `ADC1_IRQHandler`와 같은 각 handler의 vector entry 사용

## Stacking & Unstacking

- Stacking과 unstacking에는 중단된 현재 mode의 stack 사용
  - Thread mode에서 발생하면 해당 Thread의 stack에 저장
  - Handler mode에서 발생하면 실행 중인 Handler의 stack에 저장
- Stacking은 handler 실행 전 processor가 여덟 register를 자동 저장하는 동작
- Unstacking은 handler 종료 시 저장한 여덟 register를 자동 복구하는 동작
- 기본 exception frame은 full descending stack의 `32` bytes

| 새 `SP` 기준 offset | 저장 register |
| --- | --- |
| `0x00` | `r0` |
| `0x04` | `r1` |
| `0x08` | `r2` |
| `0x0C` | `r3` |
| `0x10` | `r12` |
| `0x14` | `LR`, `r14` |
| `0x18` | `PC`, `r15` |
| `0x1C` | `xPSR` |
| `0x20` | 기존 `SP` 위치 |

- Thread에서 발생한 interrupt의 실행 흐름

      ┌─────────────┐   ┌──────────┐   ┌─────────┐   ┌──────────┐   ┌─────────────┐
      │User program │──▶│ Stacking │──▶│ Handler │──▶│Unstacking│──▶│User program │
      │Thread mode  │   └──────────┘   │  mode   │   └──────────┘   │Thread mode  │
      └─────────────┘                  └─────────┘                  └─────────────┘

- Handler 실행 중 더 높은 우선순위의 interrupt가 발생하면 기존 Handler의 상태를 저장하고 새 handler 실행
  - 새 handler 종료 후 기존 Handler 상태 복구 및 실행 재개
  - 전체 흐름은 Handler mode, Handler mode, Handler mode의 순서

## Exception Exits

- Handler 실행 끝에서 `EXC_RETURN`을 `PC`에 반영하면 exception return sequence 시작
- Exception 발생 시 processor가 `EXC_RETURN`을 생성하여 `LR`에 기록
- Exception return을 시작하는 세 가지 instruction 형태

| Instruction | 동작 |
| --- | --- |
| `BX <reg>` | Register에 보존된 `EXC_RETURN` 사용, `LR`이 유지되어 있으면 `BX lr`로 복귀 |
| `POP {pc}` 또는 `POP {..., pc}` | Stack에 저장한 `EXC_RETURN`을 하나 또는 여러 register의 pop 과정에서 `PC`로 복구 |
| `LDR`, `LDM` | Destination에 `PC`를 사용하여 저장된 `EXC_RETURN`을 load |

- 일반 subroutine return과 달리 register 복구와 복귀 mode 및 stack 선택을 processor가 함께 수행함.

## Registers

- General-purpose register는 `r0–r12`
  - `r0–r7`은 low register, `r8–r12`는 high register
  - 모든 register의 폭은 `32` bits
- `r13`은 `SP`, `r14`는 `LR`, `r15`는 `PC`
- 특수 register는 `xPSR`, `BASEPRI`, `PRIMASK`, `FAULTMASK`, `CONTROL`
- Handler mode와 Thread mode의 stack 선택
  - Handler mode는 항상 Main Stack Pointer인 `MSP` 사용
  - Thread mode는 `MSP` 또는 Process Stack Pointer인 `PSP` 사용
    - `CONTROL[1] = 0`이면 `SP = MSP`, 기본 설정
    - `CONTROL[1] = 1`이면 `SP = PSP`

## Which Stack to Use When Exiting an Interrupt?

- `EXC_RETURN`은 interrupt 종료 후 활성화할 processor mode와 stack 종류 지정
- Exception 발생 당시의 processor mode와 stack 종류에 따라 동적으로 생성

| FP context | `EXC_RETURN` | 복귀 mode | 복귀 stack |
| --- | --- | --- | --- |
| 기본 frame | `0xFFFFFFF1` | Handler | `MSP` |
| 기본 frame | `0xFFFFFFF9` | Thread | `MSP` |
| 기본 frame | `0xFFFFFFFD` | Thread | `PSP` |
| FP 확장 frame | `0xFFFFFFE1` | Handler | `MSP` |
| FP 확장 frame | `0xFFFFFFE9` | Thread | `MSP` |
| FP 확장 frame | `0xFFFFFFED` | Thread | `PSP` |

- FP extension이 없는 경우 기본 frame 사용
- FP extension이 있는 processor는 저장할 FP context 여부에 따라 기본 frame 또는 FP 확장 frame 사용

## Register Values in an Interrupt Service Routine

- `MSP`를 사용하는 Thread에서 interrupt 발생 시 `LR = 0xFFFFFFF9`
- ISR은 Handler mode에서 실행하며 `SP = MSP`
- 중단된 Thread가 `PSP`를 사용하더라도 ISR 자체는 `MSP` 사용

## Interrupt: Stacking & Unstacking

### Register Changes During an Interrupt

- Main program의 `MOV r3, #0` 주소는 `0x08000044`
- `SysTick_Handler` 시작 주소는 `0x0800001C`
- `PC = 0x08000044`에서 SysTick interrupt가 발생하며 해당 main instruction은 아직 실행 전

```asm
__main PROC
      MOV r3, #0
      ENDP
SysTick_Handler PROC
      EXPORT SysTick_Handler
      ADD r3, #1
      ADD r4, #1
      BX lr
      ENDP
```

| Register | Interrupt 이전 값 |
| --- | --- |
| `r0` | `0` |
| `r1` | `1` |
| `r2` | `2` |
| `r3` | `3` |
| `r4` | `4` |
| `r12` | `12` |
| `SP`, `MSP` | `0x20000200` |
| `LR` | `0x08001000` |
| `PC` | `0x08000044` |
| `xPSR` | `0x21000000` |
| `PSP` | `0x00000000` |

- Exception entry에서 `MSP`는 `0x20000200`에서 `0x200001E0`로 감소
- 기존 `LR`은 frame에 저장되고 현재 `LR`은 `0xFFFFFFF9`로 변경
- Handler 실행 주소는 `0x0800001C`, vector entry에 저장하는 Thumb 주소는 `0x0800001D`

| Stack 주소 | 저장 대상 | 저장값 |
| --- | --- | --- |
| `0x200001E0` | `r0` | `0` |
| `0x200001E4` | `r1` | `1` |
| `0x200001E8` | `r2` | `2` |
| `0x200001EC` | `r3` | `3` |
| `0x200001F0` | `r12` | `12` |
| `0x200001F4` | `LR` | `0x08001000` |
| `0x200001F8` | `PC` | `0x08000044` |
| `0x200001FC` | `xPSR` | `0x21000000` |
| `0x20000200` | 기존 stack 영역 | 기존 내용 유지 |

| 실행 단계 | `r3` | `r4` | `LR` | `MSP` |
| --- | --- | --- | --- | --- |
| Handler 진입 | `3` | `4` | `0xFFFFFFF9` | `0x200001E0` |
| `ADD r3, #1` | `4` | `4` | 유지 | 유지 |
| `ADD r4, #1` | `4` | `5` | 유지 | 유지 |
| `BX lr`에 의한 unstacking | `3` | `5` | `0x08001000` | `0x20000200` |
| Main의 `MOV r3, #0` 실행 | `0` | `5` | 유지 | 유지 |

- Handler 안에서 `PC`는 `0x0800001C`, `0x08000020`, `0x08000024` 순서로 진행한 뒤 main의 `0x08000044`로 복귀
- `r3`의 새 값 `4`는 unstacking 과정에서 저장값 `3`으로 덮어써지므로 사라짐.
- `r4`는 hardware 자동 저장 대상이 아니므로 변경된 값 `5` 유지
- 중단된 프로그램의 `r4`를 보존하려면 handler가 직접 저장·복구해야 함.
- 실행 중인 SysTick handler의 `IPSR`은 `15`이며, 복귀 시 저장된 Thread의 `xPSR` 복구

### Calling a Subroutine Inside a Handler

- 같은 초기 상태에서 handler가 `r4`를 증가시킨 뒤 `sine` 호출

```asm
SysTick_Handler PROC
      EXPORT SysTick_Handler
      ADD r4, #1
      BL sine
      BX lr
      ENDP
```

- Handler의 `ADD` 주소는 `0x0800001C`, `BL`은 `0x08000020`, `BX lr`은 `0x08000024`
- `sine` 진입 주소를 `0x080000F0`로 둔 실행 예
- `BL sine`은 `LR`을 다음 instruction의 Thumb 복귀 값인 `0x08000025`로 갱신
  - Exception return에 필요한 `0xFFFFFFF9` 소실
  - 자동 frame에 저장된 `LR`은 main의 `0x08001000`이며 handler의 `EXC_RETURN`과 다른 값
- `sine`에서 복귀하면 `0x08000024`의 `BX lr` 실행
  - 현재 `LR`은 여전히 `0x08000025`이므로 자기 위치로 branch
  - Exception return과 unstacking이 발생하지 않으며 main 실행도 재개되지 않음.
- 자동 frame은 `r0–r3`, `r12`, `LR`, `PC`, `xPSR`의 여덟 word
  - 이전 `SP`를 별도 word로 저장하는 구조가 아니며 frame 크기와 정렬 정보로 복원

### Preserving EXC_RETURN

- 첫 번째 방법은 call 전에 `LR` 저장, call 이후 `LR` 복구 및 `BX lr`

```asm
SysTick_Handler PROC
      EXPORT SysTick_Handler
      PUSH {lr}
      ADD r4, #1
      BL sine
      POP {lr}
      BX lr
      ENDP
```

- `PUSH {lr}`가 `0xFFFFFFF9`를 자동 frame 아래에 추가 저장
- `MSP`는 `0x200001E0`에서 `0x200001DC`로 감소하며, `POP {lr}` 후 `0x200001E0`로 복구
- 두 번째 방법은 저장한 `LR`을 `PC`로 직접 pop하여 exception return 시작

```asm
SysTick_Handler PROC
      EXPORT SysTick_Handler
      PUSH {lr}
      ADD r4, #1
      BL sine
      POP {pc}
      ENDP
```

- 세 번째 방법은 call 이후 `EXC_RETURN` 상수를 `LR`에 직접 기록

```asm
SysTick_Handler PROC
      EXPORT SysTick_Handler
      ADD r4, #1
      BL sine
      LDR lr, =0xFFFFFFF9
      BX lr
      ENDP
```

- 상수 직접 기록은 Thread와 `MSP`로 복귀하는 상황에만 맞으므로 권장하지 않음.
- 실제 handler는 변경한 callee-saved register 보존과 public interface의 `8`-byte stack 정렬도 필요
  - `PUSH {r4, lr}`와 `POP {r4, pc}`를 사용하면 `r4`와 `EXC_RETURN` 보존 및 정렬을 함께 만족

## Interrupt Number in PSR

- ARMv7-M의 exception 번호 공간은 `1–511`
  - Reserved 번호 제외
  - Thread mode의 exception number는 `0`
- `xPSR`의 하위 `9` bits인 `IPSR[8:0]`에 현재 exception number 표시

| Bit | Field | 의미 |
| --- | --- | --- |
| `31` | `N` | Negative 또는 less-than flag |
| `30` | `Z` | Zero flag |
| `29` | `C` | Carry/borrow flag |
| `28` | `V` | Overflow flag |
| `27` | `Q` | `SSAT`, `USAT`의 sticky saturation flag |
| `26–25` | `IT[1:0]` | If-Then 상태의 일부 |
| `24` | `T` | Thumb state flag |
| `23–20` | Reserved | 예약 영역 |
| `19–16` | `GE[3:0]` | Greater-or-equal flag, Cortex-M4 및 M7에서 제공 |
| `15–10` | `IT[7:2]` | If-Then 상태의 나머지 |
| `9` | Reserved | 예약 영역 |
| `8–0` | Exception number | Thread의 `0` 또는 현재 exception 번호 |

## Enable an Interrupt/Exception

- System exception의 번호 영역은 `0–15`, 실제 exception은 `1`부터 시작
  - 일부 exception은 항상 활성화되어 disable 불가능
  - Enable/disable을 위한 하나의 중앙 register는 없음.
  - SysTick module처럼 각 exception에 대응하는 구성 요소에서 제어
- Peripheral interrupt는 exception 번호 `16`부터 시작
  - Enable/disable을 위한 중앙 register array 제공
  - NVIC의 `ISER0–ISER15`는 Interrupt Set Enable Register
    - Register당 `32` bits, `16`개 register의 bit 공간은 `512`개
    - 실제 peripheral interrupt의 최대 지원 수는 `496`개
  - NVIC의 `ICER0–ICER15`는 Interrupt Clear Enable Register
    - 해당 bit에 `1`을 써서 `ISER`로 설정한 enable 상태 해제
- `ISER`와 `ICER`에서 `0`을 쓴 bit의 기존 상태는 유지됨.

## Enabling Peripheral Interrupts

- `TIM7_IRQn = 44`인 Timer 7 interrupt 활성화
- Register index는 `44 / 32 = 1`, register 내부 bit는 `44 % 32 = 12`

```c
NVIC->ISER[1] = 1 << 12;
```

- `ISER[0]`은 IRQ `0–31`, `ISER[1]`은 IRQ `32–63`에 대응
- `ISER[1]`의 주소는 `ISER[0]`의 주소에 `4`를 더한 위치
- Timer 7의 exception 번호는 `44 + 16 = 60`

## Disabling Peripheral Interrupts

- 동일한 Timer 7 interrupt를 비활성화하려면 `ICER[1]`의 bit `12`에 `1` 기록

```c
NVIC->ICER[1] = 1 << 12;
```

- `ICER[0]`은 IRQ `0–31`, `ICER[1]`은 IRQ `32–63`에 대응
- `ICER[1]`의 주소는 `ICER[0]`의 주소에 `4`를 더한 위치

## Priority Management

- 고정 priority와 설정 가능한 priority, preemption 및 masking 제어

## Interrupt/Exception Priority

- Priority 수치와 urgency는 반비례
  - Priority 값이 작을수록 높은 urgency
    - Interrupt A의 priority가 `5`, B의 priority가 `2`라면 B가 A보다 높은 우선순위
- Reset, NMI, HardFault의 priority는 고정

| Exception | Exception 번호 | CMSIS `IRQn` | 고정 priority |
| --- | --- | --- | --- |
| Reset | `1` | 해당 없음 | `-3`, 최고 |
| NMI | `2` | `-14` | `-2`, 두 번째 |
| HardFault | `3` | `-13` | `-1` |

- 나머지 구현된 interrupt와 exception은 priority 조정 가능

## Peripheral Interrupt Priority

- Interrupt Priority Register인 `IPR0–IPR123`으로 peripheral interrupt priority 설정
  - `124`개 register에 각각 네 개의 priority byte 배치
  - `124 * 4 = 496`개의 peripheral interrupt priority 설정 가능
- 각 priority는 preemption priority와 sub-priority의 두 field로 구성
  - Priority byte에서 실제 사용할 수 있는 bit 수는 device 구현에 따라 `3–8` bits
    - 구현된 bit는 byte의 상위 bit부터 배치
  - Preemption priority는 실행 중인 handler를 선점할 수 있는지 결정
  - Sub-priority는 preemption priority가 같은 여러 pending interrupt의 처리 순서 결정
- 유효 priority bit 안에서 두 field의 길이 설정 가능
  - Preemption priority field는 MSB 쪽에 위치
- 상위 `4` bits를 구현하고 preemption priority와 sub-priority에 각각 `2` bits를 할당한 배치 예

| Priority byte의 bit | 용도 |
| --- | --- |
| `7–6` | Preemption priority |
| `5–4` | Sub-priority |
| `3–0` | 미구현 영역 |

- Preemption priority를 상위에 배치하는 이유는 이식성
  - Priority bit가 많은 device의 프로그램을 bit가 적은 device로 옮겨도 우선순위 역전 방지
  - Preemption priority `2` bits와 sub-priority `4` bits에서 각각 `2` bits인 구성으로 축소하는 예

| Field 순서 | 기존 priority byte | 기존 `PP`, `SPN` | 축소 후 `PP`, `SPN` |
| --- | --- | --- | --- |
| 상위 `PP`, 하위 `SPN` | `0b00000100` | `0`, `1` | `0`, `0` |
| 상위 `PP`, 하위 `SPN` | `0b00010000` | `0`, `4` | `0`, `1` |
| 상위 `SPN`, 하위 `PP` | `0b01000100` | `1`, `4` | `0`, `1` |
| 상위 `SPN`, 하위 `PP` | `0b00010000` | `0`, `1` | `1`, `0` |

- `PP`는 preemption priority, `SPN`은 sub-priority number
- 상위 `PP` 배치는 유효 bit 감소 후에도 두 요청의 우선순위 순서 유지
- 상위 `SPN` 배치는 기존 `PP = 0`의 요청이 축소 후 `PP = 1`이 되어 우선순위 역전 발생

## System Interrupt Priority

- 세 개의 System Handler Priority Register인 `SHPR1–SHPR3`로 system exception priority 설정
- 각 register는 `32` bits이며 네 개의 byte 위치 포함
- `base`는 `SHPR1`의 시작 주소

| Register | Byte offset | Exception 번호 | Priority 대상 |
| --- | --- | --- | --- |
| `SHPR1` | `base + 0` | `4` | MemManage |
| `SHPR1` | `base + 1` | `5` | BusFault |
| `SHPR1` | `base + 2` | `6` | UsageFault |
| `SHPR1` | `base + 3` | `7` | Reserved |
| `SHPR2` | `base + 4` | `8` | Reserved |
| `SHPR2` | `base + 5` | `9` | Reserved |
| `SHPR2` | `base + 6` | `10` | Reserved |
| `SHPR2` | `base + 7` | `11` | SVCall |
| `SHPR3` | `base + 8` | `12` | Debug Monitor |
| `SHPR3` | `base + 9` | `13` | Reserved |
| `SHPR3` | `base + 10` | `14` | PendSV |
| `SHPR3` | `base + 11` | `15` | SysTick |

## Exception-Masking Registers

- `PRIMASK`는 설정 시 현재 execution priority를 `0` 수준으로 제한
  - NMI, HardFault, Reset을 제외한 설정 가능한 priority의 interrupt와 exception 차단

```asm
MOV r0, #1
MSR PRIMASK, r0
```

- `FAULTMASK`는 설정 시 현재 execution priority를 `-1` 수준으로 제한
  - NMI와 Reset을 제외한 모든 exception 차단
- `BASEPRI`는 지정한 값과 같거나 더 낮은 urgency의 interrupt 차단
  - Priority 값이 `0x60` 이상인 interrupt를 차단하는 예

```asm
MOV r0, #0x60
MSR BASEPRI, r0
```

- `BASEPRI = 0`이면 해당 priority threshold에 의한 masking 해제
